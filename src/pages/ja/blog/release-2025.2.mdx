新しいリリースにはいくつかの嬉しい機能が含まれていますが、そのほとんどは DM とサーバー所有者向けです。

簡単なまとめ:

- サーバーの設定形式が完全に変更されました
- サーバー管理者がメールサーバーを設定できるようになり、「パスワードを忘れた場合」のフローが利用可能になりました
- isToken プロパティが削除され、シェイプのアクセス権の動作が変更されました
- 実験的な Mod サポートがいくつか改善されました
- 前回のリリースで刷新されたゲーム内アセットマネージャーのフォローアップ
- サーバーに匿名統計の収集機能が追加されました

<Warning title="サーバーの変更">
    サーバー所有者の方へ: サーバーの設定は大幅に変更されており、手動での対応が必要です。詳細は下記をご覧ください!

    また、サーバーは依存関係の管理に UV を使用するようになったため、アップグレードに影響が出る可能性があります。

</Warning>

## メール

長らく待たれていた機能ですが、サーバー所有者は(新しい)設定でメールサーバー情報を構成できるようになりました。設定すると、PA はこれを利用してプレイヤーにメールを送信できます。

現在、利用できる用途は 1 つだけですが、それは重要なものです。「パスワードを忘れた場合」のフローです。

_関連情報: [メール設定セクション](/ja/server/management/configuration/#mail)_

### パスワードを忘れた場合

メールが設定されている場合、ログイン画面のパスワード欄の下に「パスワードをお忘れですか?」というアクションが表示され、指定したメールアドレスでパスワードをリセットできるフローが提供されます。

これはユーザーがメールアドレスを設定している場合にのみ機能することに注意してください(登録時のメールアドレスは任意です)。

関連する小さな改善として、ダッシュボードでメールアドレスを変更すると、成功通知が表示されるようになりました。これまでは、変更が実際に適用されたかどうかが分かりにくかったのです。

## 視線描画の無効化

DM であれば、新しいロケーションで作業していて照明を設定したものの、視線(LoS)が有効でプレイヤーがまだ別のロケーションにいるため、照明が期待通りに届いているかどうか確信が持てない、という状況に心当たりがあるかもしれません。

これにはさまざまな「回避策」があります。視野権限を持つ一時的なシェイプを作成する、ロケーション設定で LoS を一時的に無効にする、などです...

どれも機能しますが、手間がかかりやすく、ミスを誘発することもあります(たとえば、プレイヤーをロケーションに迎える準備ができたときに LoS 設定をオンに戻すのを忘れるなど)。

そこで、ツールバーの下に DM 用の新しいクイックトグル「LOS」が追加されました。これはロケーションで LoS が有効な場合にのみ表示されます。緑(オン)と赤(オフ)のモードがあり、純粋に自分のローカルクライアント上だけで LoS 設定を上書きできます。

これにより、プレイヤーに影響を与えずに動作のオン/オフをすばやく切り替えられるため、レベルデザインが簡単になります。

_関連情報: [クイックトグル](/ja/docs/tools/quick-toggles/)_

## アクセスレベルと isToken

PA のすべてのシェイプには、プレイヤーごとに細かく調整できるアクセスレベルがあります。一部のプレイヤーにはシェイプの完全な編集権限を、他のプレイヤーには視野アクセスのみを許可できます。

これまで、これらのアクセスレベル(視野/移動/編集)は累積的でした。各アクセスレベルは、その下のアクセスレベルに関連するすべての権限も与えていました(たとえば、移動には視野の権限も含まれていました)。これは PA の歴史の大半において基本設計としてうまく機能してきましたが、最近、この累積的な性質のために実現できなかった解決したい問題にいくつか遭遇しました。

アクセスレベルは今後、完全に分離されます。たとえば、視野アクセスなしで編集アクセスを持つことが可能になりました。これは、プレイヤーがペットのステータスを管理できる一方で、ペットが見ているものは見えない場合などに便利です。

さらに、すべてのシェイプには `isToken` という特別なプロパティがありました。これは LoS が有効な場合の視野計算に不可欠で、プレイヤーのシェイプはすべて有効にしておく必要がありました。しかし、このプロパティは多くの新規プレイヤーにとってあまり直感的ではなく、ベテランのプレイヤーでさえ、LoS のために有効にする必要があることを除けば、実際に何をするものなのかよく分かっていません。

これはずっと以前にパフォーマンス上の理由から導入されましたが、しばらく考えた結果、アクセスレベルの仕組みを変更すれば実際には不要であることが分かりました。その結果、`isToken` プロパティは削除され、ユーザーのシェイプにこれを手動で設定する必要はなくなりました。代わりに、視野アクセス権を持つシェイプはすべて、以前は isToken が設定されていたかのように描画されます。

これらの変更を行った理由について詳しく知りたい場合は、[詳細なブログ記事](https://www.planarally.io/blog/removing-is-token/)を執筆しました。

_関連情報: [シェイプのアクセス](/ja/docs/game/shapes/#access)_

## アセット

ダッシュボードのアセットマネージャーには、フォルダー作成/ファイルアップロード/選択範囲削除の専用ボタンがありましたが、ゲーム内バージョンにはありませんでした。ファイルの追加や選択範囲の削除はマウスのドラッグ&ドロップやコンテキストメニューで可能でしたが、フォルダーの作成はできませんでした。

これらのボタンが、ゲーム内アセットマネージャーにも追加されました。

さらに、古いアセットピッカー UI をまだ使用していた場所(キャンペーンロゴの設定など)は、すべて前回のリリースで導入された新しい UI に更新されました。

## 統計の収集

よく受ける質問の 1 つが、PA の実際のユーザー数です。私はこれに答えることも、推定することもできませんでした。

推定の基にできる公式の PA サーバーはありません。github のスター数や discord のユーザー数などの漠然とした数字しかありませんが、それらは実際のユーザーについては何も示しておらず、むしろプレイヤーではなくサーバー所有者を表している可能性が高いです。

実際に何が起こっているのかを把握するため、サーバーに統計収集機能を導入します。これは将来のリリースで、ローカルサーバー管理に対して行いたい変更とも連携し、適切な権限があればダッシュボードでもこれらの統計を確認できるようになります。

収集される統計は非常に単純で、いかなる個人情報も含みません。実際に何人のユーザー/キャンペーンが利用されているかについて、私にほんの少しの手がかりを与えるだけです。

収集される統計の詳細とプライバシーの扱いについては、[github PR](https://github.com/Kruptein/PlanarAlly/pull/1608) を参照してください。詳細な情報が記載されています。

サーバー所有者は、新しい設定形式でこの機能を構成できます。

## Mod の更新

_Mod のサポートはまだ非常に実験的な段階であることにご注意ください_

1 年前に Mod の初期サポートが追加されました。これはまだ非常に粗いもので、大きな問題の 1 つが、サーバー所有者だけが特定のフォルダーに手動で追加することで Mod を導入できるという点でした。今回のリリースではキャンペーンごとの UI が追加され、DM がそのキャンペーンで使用する Mod をアップロードできるようになりました。

さらに、Mod API の内部の多くが更新されました。特に DataBlock API は大幅に変更され、Mod の UI 側がはるかにコンパクトになりました。

planarally-mods リポジトリ内のすべてのサンプル Mod も新しい API に更新されています。

_関連情報: [Mod PR](https://github.com/Kruptein/PlanarAlly/pull/1583)_

## サーバー: 設定の変更

設定形式は完全に変更され、サーバーフォルダー内での保存場所も変更されました。現在は toml ベースの形式で、データフォルダーに保存されます。この変更には複数の理由があり、ずいぶん前から必要とされていました。

詳細な理由と情報については、[github PR](https://github.com/Kruptein/PlanarAlly/pull/1574) を読むことを**強く**お勧めします。

サーバー関連のドキュメントは、すべての[設定オプション](/ja/server/management/configuration/)を表示するように更新されました。

既存の設定ファイルのアップグレードでお困りの場合は、遠慮なく discord サーバーの #help チャンネルに連絡してください。

## サーバー: 依存関係管理の変更

サーバーは依存関係の管理にも [UV](https://docs.astral.sh/uv/) を使用するようになりました。

つまり、python/pip でサーバーを手動管理している場合は、uv をインストールして新しいシステムにも対応する必要があります。該当するユーザーは少数なので、影響は小さいはずです。

詳細については、[github PR](https://github.com/Kruptein/PlanarAlly/pull/1550) と、uv の使い方に関する情報が更新されたサーバーの readme を確認してください。

## バグ修正

- Draw ツールのポリゴンが、シェイプが完成するまで視野を更新しない問題
- プレイヤーが所有していないトークンシェイプが移動された際のレンダリングオーバーヘッドを削減
- オプションを選択してもシェイプのコンテキストメニューが閉じない問題
- モード切り替え時に Select ツールの Build UI が表示されない問題
- ルームとユーザーカテゴリの DataBlock に、サーバー側で作成を妨げるバグがあった問題
- アセットのコンテキストメニューの削除が機能しない問題
- ゲーム内でアセットのコンテキストメニューの背景色が時々間違って表示される問題
- ダッシュボードのアセットマネージャーにアップロードバーが表示されない問題
- 共有表示権限のあるアセットをマップにドロップしても機能しない問題
