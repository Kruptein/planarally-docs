しばらくぶりです。新リリースをずっと待ち望んでいました!
リリースはそれほど大きくはありませんが、遊べる楽しい新しいツールがいくつかあり、いつも通り一連のバグ修正も含まれています。

## 仮想ダイス

最初の大きな機能は、仮想ダイスロールです!
ただし、一つ注意点があります。このリリースに含まれるバージョンはまだ洗練されていません。
ダイスローラーの将来を形作るために、使い心地についてのフィードバックを得たいと思っています。

ダイスのロールは、プレイモードの専用ツールとして利用でき、DM とプレイヤーの両方が使えます。
ダイスのセット（現在は dX ダイスに限定）を構築し、画面上で転がすことができます。
結果は画面上のダイアログに表示され、ダイスツール自体にも記憶されます。

オプションで、ダイスの結果をすべてのプレイヤーと共有することを選択できます。その場合、ロールしたときに各プレイヤーの画面に小さな通知が表示されます。
（つまり、ダイスは他のプレイヤーの画面では視覚的に転がされません）

#### 動作に関する注意

ダイスは、適切な物理システムでエミュレート/近似されています。PA がダイスが最終位置に着いたと判断して結果を表示しても、その後もう一度だけダイスが転がることがあり得ます。これらの問題は将来修正される予定です。キャンペーンで頻繁に使用するつもりなら、どの値を実際の値として扱うかを事前に決めておくのが賢明かもしれません。

#### 読み込みに関する注意

ダイスは完全な 3D レンダリングシステムを使用しています（babylonjs と ammojs に感謝!）。これにより依存関係を通じて多くの余分なコードが取り込まれ、バンドルサイズが大幅に増加し、その結果 PA の読み込み時間が長くなります。

これを回避するため、ダイス関連のコードはすべてメインの PA 読み込み中には読み込まれず、ダイスツールを最初にクリックした時まで延期されます。つまり、ダイスツールを最初に操作するときには、少し遅延があるかもしれません。

## Draw ツールのポインター

少し前に、Draw ツール使用時のマウスポインターを表示しないという決定が下されました。それは、PA の描画ループと 100% 同期しているわけではなく、実際のカーソルとゲーム内で想定されるカーソルの間に視覚的なラグが生じるためです。

同期していないカーソルがなくなったことで、描画操作はよりスムーズに感じられますが、キャンバスのどこにいるのかを見失いやすくなりました。これは、透明な色やマップの背景に非常に近い色で描画している場合にさらに顕著です。

このリリースではマウスカーソルが再追加されました。実際の OS のマウスカーソルではなく、PA 自体の単なるポリゴンである偽のマウスカーソルです。これは PA のシェイプであるため、描画ループと常に同期し、スムーズに感じられます。

## ポリゴン編集ツール

ポリゴンが導入されてから長い間、特に照明や視野関連のすべてにおいて、ポリゴンは私が最も使うシェイプになりました。

特定の壁に秘密の扉があったのを忘れてしまい、セッション中にそれを修正するのが難しいことがあります。壁全体を削除してやり直さなければならないため、ポリゴンの長さによっては大きな苦痛になり得ます。あるいは、キャラクターを壁に通すだけ、というのが私が主に取る方法です。

この状況はもう必要ありません。ついに既存のポリゴンを修正するツールを追加したからです!

ビルドモードでポリゴンを選択すると、ポリゴンの近くに追加の UI が表示され、マウスに追従します。
エッジの上にカーソルを置くと、ポリゴンに追加のポイントを追加するか、その点でポリゴンを分割するかを選択できます。
ポイントの上にカーソルを置くと、そのポイントを削除できます。

## SVG 壁の処理

リリース 0.26.0 以降、svg ファイルの形式で壁情報を PA のほぼすべてのオブジェクトに添付できるようになりました。ただし、主な使用例は明らかにマップです。
svg からパス情報を抽出し、素早くアクセスできるようにシェイプのオプションに保存していました。

古いパス抽出は、要素に設定された可能性のある変換（例: translate/scale）を無視していたため、PA で正しい結果を得るために、場合によっては svg を手動で y 軸方向に反転する必要がありました。

新しい svg 処理の実装が書かれ、アセットに関連付けられたパス全体を保持するのではなく、実際の svg への参照のみを保持し、それをその場で別途解析するため、svg 処理への将来の改善を既存のアセットにも適用できます。

そのような改善の一つが、translate と scale 変換のサポートです。

既存の svg フローを壊したくなかったため、新しく改良された svg 処理の恩恵を受けるには、svg を再適用する必要があります。

将来的には古い svg 処理コードを削除するつもりなので、使用している svg マスクをすべて再適用することを強くお勧めします。適用しないと将来動作しなくなる可能性があります（詳細は後日お知らせします）。

## UI の改善

### アクティブなツールモード

前回のリリースでは、ツールモード（つまり Play と Build）に関連する UI が変更されました。
どちらのモードが現在アクティブかを明確にするため、両者の区別がさらに強化されました。

### 視野設定

最小視野範囲より小さい最大視野範囲を設定することはできなくなりました。逆も同様です。

### 角度 UI

Aura は通常、完全な 360 度の円ですが、表示角度とともに設定して、Aura を特定の方向に向けることができます。
表示角度の UI にも、より正確にしたい場合や円形の入力要素が好みでない場合のために、数値入力が用意されました。

### バリアント切り替え

バリアント切り替えは、大きな vue3 更新の際に無効になりました。一部は、私がバグが多すぎて他の人が実際に使っていないと感じたためです。

私はその評価についてどうやら大きく間違っていたようです。バリアントが機能しなくなった理由について複数の質問を受けたからです。

申し訳ありません。元の機能で再び有効になりました!

#### 修正

バリアントを持つシェイプに関連する 2 つのバグも修正されました:

##### トラッカー/Aura

共有トラッカー/Aura ロジックにいくつかの論理の問題があり、その結果動作が一貫しないものになっていました。

これで正しく動作するはずです :)

さらに、バリアントを変更した際、以前のバリアントに（複数の）非共有 Aura があった場合、それらの一部が画面に残るものの、一緒に移動しない（つまり静的になる）問題がありました。これも解決されました。

##### ロケーション変更

バリアントを持つシェイプを別のロケーションに移動した際、バリアントの一部しか移動されず、あらゆる場所で複数の問題が発生していました（古いロケーションが読み込めなくなることを含む）。
