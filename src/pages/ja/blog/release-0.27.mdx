前回のリリースからしばらく時間が経ちました。
良い知らせとしては、バグの報告が少なかったため、0.26 リリースはかなり安定していました。これはいつも喜ばしいことです。
悪い知らせとしては、今回のリリースは少し荒れるかもしれないということです。その理由は後ほど明らかになります。

今回のリリースの主な目的は一つだけでした。それは、PA が使用しているリアクティブフレームワーク（Vue）をバージョン 2 からバージョン 3 にアップグレードすることです。
これは非常に技術的な変更であり、_理想的には_ ユーザー体験に直接影響を与えるべきものではありませんが、触れるコードが非常に多いため、正しく動作するかを確認するために長めの期間を取りたいと考えていました。実際のユーザーの皆さんを怖がらせないよう、変更内容の詳細についてはこの記事の最後で詳しく説明します。:)

しかし、内部コードの変更だけが変わったわけではありません。イニシアチブが刷新され、PA を物理的なゲームボードとして使用するための新しい機能もいくつかあり、コミュニティからの素晴らしい貢献も再びありました。それでは詳しく見ていきましょう！

## イニシアチブ

これまで機能していたイニシアチブツールは、reddit のコメントでイニシアチブのサポートを求められた後、ほぼ数日で作られたものでした。役割は果たしていましたが、常にいくつかの小さな問題を抱えていました。私はようやく時間を取って、これらの未解決の問題に対処し、イニシアチブの機能の一部を再考しました。

![イニシアチブツールの改良](./0.27/initiative.png)

### UI/UX

問題の一つは、UI が非常にごちゃごちゃしやすいことでした。
特に、常に DM 用のボタンが見えるのに、何も操作できないプレイヤーにとってはそうでした。

#### DM バー

DM 専用の操作は別の「DM バー」に移動され、（共同）DM にのみ表示されるようになりました。

#### 設定

それに伴い、カメラと視野ロックのアイコンはクライアント設定に移動され、小さな歯車アイコンからアクセスできるようになりました。
これにより、これらの設定を頻繁に使用する人々が、これまで毎回これらの構成を再適用しなければならなかったという「バグ」も解消されました。

#### 削除

もう一つの顕著な変更は、各イニシアチブ参加者のアイコンからゴミ箱が削除されたことです。
常に見える必要があまりないものとしては、場所を取りすぎていました。
代わりに、イニシアチブ参加者の上にカーソルを置くと、右上隅に小さな赤い×印が表示されるようになりました。

#### 入力フィールド

最後に、入力値自体に幅が持たせられました。余裕ができたのです！
また、スタイルも変更され、奇妙な入力ボックスとして浮くことはなくなり、モーダル内の「普通の」要素のように見えるようになりました。

イニシアチブを入力しているときに、他の誰かが同時に値を変更すると、イニシアチブが飛び跳ねて入力フィールドのフォーカスが外れてしまうことがあります。これは以前、イニシアチブウィンドウの更新を自分の変更を送信するまで待つことで対処されていました。しかし、入力フィールドにフォーカスを当てたままの場合、値が同期されていないことを示す表示はありませんでした。これは非常にわかりにくく、多くの混乱を招く可能性があるため、理想的ではありません。そのため、新しいイニシアチブウィンドウでは、入力フィールドにフォーカスしている間、他のすべてのイニシアチブの行がぼやけて表示され、まだ完了していない操作を行っていることを視覚的に示すようになりました。

![イニシアチブのぼかし](./0.27/blur.png)

最後の品質改善として、イニシアチブの入力フィールドでも `enter` キーが使えるようになりました :)

### 動作

旧イニシアチブのもう一つの問題は、並べ替え動作が固まってしまい、イニシアチブの順序が更新されなくなったり、誤って更新されたりすることでした。この原因となっていた裏方のデータ構造が変更され、今後は常に正しく動作するはずです。

イニシアチブの DM バーにも新しい機能が加わりました:

誰かをうっかり飛ばしてしまった場合や、誰かが自分のターンを終えていない場合に、過去に戻ることができるようになりました。
また、すべてのイニシアチブ値をクリアすることもできるようになりました。これにより、新しいイニシアチブを呼び出して、誰がまだ値を更新していないかを確認できます。それ以外の場合は、値が新しいものか、まだ古いものかを確認するのが難しいかもしれません。

#### 並べ替え

最後に、並べ替え動作を積極的に変更できるようになりました。3 つのオプションがあります: 降順、昇順、手動です。
イニシアチブをドラッグすると、同じイニシアチブ値を持つ二人の参加者を入れ替えない限り、並べ替えは自動的に手動モードに切り替わります。

## ロケーションのコピー

_CalebKoch 氏による貢献_

この便利な機能により、DM はロケーションを別のセッションにコピーできます。コンセプトは非常にシンプルですが、同じキャンペーンを複数のグループで運営している場合、マッピング全体や戦争の霧の描画をやり直す必要がなくなり、多くの手間を省けます。

コピー元にしたいロケーションの設定から、DM としてアクセスできます。ダイアログに、持っているすべてのキャンペーンが表示されます。

## ゲームボード

これは一部、私が協力して PA をプラットフォームに導入している last gameboard の関係者からの要望によるものですが、
一般的な用途もあります!

![物理ゲームボードの寸法](./0.27/gameboard.png)

ほとんどの場合、PA はテーブルトップゲームの純粋なデジタルソリューションとして使用されます。
この文脈では、グリッドのセルが表すべきピクセルサイズが何よりも重要です。

一方、PA が「伝統的な」物理プレイの拡張として使用され、追加機能を備えたより伝統的なゲームボードとして使われる場合もあります。
この文脈では、ピクセルサイズを直接入力することはあまり重要ではなく、ミニをボードに置けることが重要です。

これで、ミニのサイズと画面の PPI（DPI と呼ばれることもあります）を指定することで、物理的な文脈でグリッドのサイズを定義できるようになりました。この結果の一つとして、ズームは意味をなさなくなり、現時点では動作しません。

## ビューポート

DM として、自分の DM 用画面を持ちながら、プレイヤーが見ている内容を表示する別の画面も操作することがあります。
この文脈では、プレイヤーのカメラを操作するために画面やデバイスを切り替えるのが面倒なことがあります。

今回のリリースで新しくなったのは、プレイヤーのアクティブなビューポートを表示するオプションです。Admin 設定で、個々のプレイヤーのビューポートを切り替えることができます。

各ビューポートは、DM レイヤー上に塗りつぶしのない長方形として描画され、その境界線が、その時点でプレイヤーが見ている正確な領域を示します。

さらに、各ビューポートは DM が移動させることができ、関連するプレイヤーの画面を直接パンできます。

## 品質改善

大きな変更は以上ですが、素晴らしい品質改善も多数行われました!

### アセットメニューの同期

アセットメニューのサイドバーは、現時点では DM にのみ提供されていますが、アセットマネージャーに新しいアセットが追加されても、ライブで更新されることはありませんでした。
これにより、私自身を含む多くの人が、新しいアセットを追加するたびにページをリロードする必要があり、非常に苦労していました。

もうこれに耐える必要はありません。バーがアセットマネージャーの状況に合わせてライブ更新されるようになったからです!

### シェイプのテキスト値の編集

一部のシェイプ（例: Text や CircularToken）には、特定のテキスト値が関連付けられています。
これまでは、この値はこれらのシェイプの作成時にのみ設定でき、その後は変更できませんでした。

これらのシェイプの編集ダイアログのプロパティタブに、新しい「値」の行が追加されました。

### HiDPI/Retina

以前の画像でお気づきかもしれませんが、クライアント設定に新しい表示タブが追加されました。
そこには、HiDPI と retina スクリーンのサポートを有効にするトグルも含まれています。
これにより、すべてがよりシャープになるはずです!

**警告**:

- コンピューターの描画負荷が高くなります
- この設定を有効にするとズームやパンがおかしくなるという報告をいくつか受けていますので、ご注意ください!

### ctrl による選択解除

Ctrl を押しながらシェイプをクリックすると、アクティブな選択に個々のシェイプを追加できます。他のツールでは、選択済みのシェイプを Ctrl クリックして選択を解除することも一般的にサポートされています。これも今回サポートされました。

### プレイヤー追放の確認

プレイヤーを追放する際には、まず確認を求めるようになりました :)

## サーバー

### api サーバーはデフォルトで無効になりました

API サーバーは非常にニッチな機能で、デフォルトで有効になっていたため、追加のポートを開く必要がありました。
メインポートしか開いていないコンテナで実行している人々に不可解なエラーメッセージが出ないよう、デフォルトで無効になりました。

### public_name はデフォルトでコメントアウトされました

_dthv 氏による貢献_

これがオプションの機能であることを明確にする小さな品質改善です。

### Dockerfile の変更

_jirsat 氏による貢献_

dockerfile から使用されていない依存関係がいくつか削除され、ARM のサポートが追加されました。

## 修正

- 上の方のフロアにあるフロアと照明に関するバグが更新されない問題
- リフレッシュまでフロアの並べ替えが正しく描画されない問題
- Mac で Redo が機能しない問題
- 負の値のトラッカーバーが左向きのバーとして表示される問題
- 共同 DM が非公開のイニシアチブを見られない問題
- 最後のフロアを削除すると空白画面になる問題
- アクティブなフロアより下のフロアを削除すると空白画面になる問題
- unitSize に &lt; 1 の値を設定できた問題

## クライアント書き換えの詳細

冒頭で述べたように、PA は現在 Vue 3 を使用しており、より TypeScript に親和的な composition API が導入されました。

すべての UI コードは、この新しい API を活用するために完全に書き直されました。
さらに、すべての「ストア」は、私自身のニーズに合わせて作成した非常にシンプルな独自の状態 API を使用するように書き直されました。
これにより、これまで純粋な ts ファイルと関連ストアに分散していた多くのコードをリファクタリングすることができました。

Vue 3 のもう一つの素晴らしい利点は、リアクティブな文脈で Map と Set をサポートするようになったことです。これにより、Map のようなデータをより理想的な方法で扱えない領域が大幅に改善されました。
