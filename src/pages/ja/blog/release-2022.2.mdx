## インポート/エクスポート

最も目立つ新機能はインポート/エクスポート機能です。
エクスポート機能は前回のリリースで API 限定の機能（つまりエクスポート用の UI がない）としてすでに追加されていましたが、
インポート機能はまだ定義されていませんでした。

_余談ですが、このエクスポート機能のおかげで、いくつかのバグ修正をより早く解決することができました！_

今回のリリースでは、インポート機能に加え、エクスポートとインポートの両方の UI が追加されたため、エンドユーザーも利用できるようになりました。

### 実験的機能

この機能はまだ最終的な形ではないことを強調しておきますが、非常にニッチな機能であるため、
テストしていただけるよう公開しても問題ないと判断しました。

注意すべき点は次のとおりです。

- UI は非常に最小限で、インポート/エクスポートはどちらも単一のボタンのみで、進捗情報はありません。
- クライアント側のエラー情報もまだありません
- すでに実行中のキャンペーンと同じ名前のキャンペーンはインポートできません
- インポートできるのは、エクスポートしたサーバーと同じかそれより新しいバージョンのサーバーでのみです

最初の 2 点は今後のリリースで対応します。
3 点目は UI/UX の問題で、別のキャンペーン名を指定する方法を提供する必要があります。
最後の点は明白な技術的制限です。古いサーバーは保存形式の変更内容を知る術がないためです。

この問題に取り組むには、任意のバージョン間で保存ファイルをアップグレード/ダウングレードできる別のサービスを作成する必要があります。これはかなりの作業が必要なので、あまり早く実現するとは期待しないでください。

### エクスポート/インポートの方法

エクスポートとインポートの両機能には、メインのダッシュボードからアクセスします。ゲーム内ではありません！

自分が DM を務めるキャンペーンをエクスポートするには、「run」セクションのキャンペーンをクリックし、サイドバーの「export」ボタンをクリックします。
エクスポートが完了すると（サーバー側で失敗しなければ）、ブラウザからファイルのダウンロード要求が表示されます。エクスポートは即時ではありませんが、非常に長くもかかりません。

エクスポートされたキャンペーンの出力は、拡張子が「.pac」（PlanarAlly Campaign の略）の単一のファイルです。
このファイルには、エクスポートされたキャンペーンで使用されているすべてのアセットと、キャンペーンに関連するデータベースのすべての情報が含まれます。

そのキャンペーンを別のサーバーにインポートするには、ナビゲーションサイドバーの「import」セクションに移動し、シンプルなボタンを押します。
完了すると、「run」セクションにリダイレクトされ、インポートしたキャンペーンが一覧に表示されます。

エクスポートとインポートの所要時間は、キャンペーンの規模（#ロケーション、#フロア、#シェイプ）と、それらのキャンペーンで使用されるアセットのサイズに応じて変わります。

### これはいつ使うの？

この機能の実際の用途は何かと疑問に思われるかもしれませんが、多くの人はサーバーを 1 台使い続けるだけで、エクスポート/インポートを気にする必要はないでしょう。

いくつかの潜在的な使用例を挙げます。

1. バグを見つけた、何かがうまく動いていない、そして私とのやり取りでは何が問題なのかすぐに明確にならない場合。
   これはキャンペーンをエクスポートして私に送る絶好のタイミングです。私が自分のペースでデバッグできるので、あなたとやり取りを繰り返す必要がありません。

2. 自分でバックアップを取りたい場合。使用しているサーバーで何か問題が発生する可能性は常にあります。バックアップを取っておいても害はありません。

3. インターネットがない場所でプレイする予定がある場合。キャンペーンをすばやくエクスポートし、
   ローカルサーバーでインポートすれば、中断したところからプレイを続けられます。
   再びインターネット環境に戻ったら、インポートし直すこともできます！

4. 単に別の PA サーバーに移行したい場合。

## カラーピッカー

カラーピッカーに楽しい新機能が追加され、私が気になっていた 2 つのバグも修正されました :D。

### 以前使用した色の記憶

カラーピッカーは、使用した色を記憶するようになりました（\*）。
それらはピッカーの下部に 2 行で表示されます（最大 20 色を記録）。これらの色をクリックすると、現在の色として設定できます。リスト内の色にカーソルを合わせると、その色の rgba 値も表示されます。

色の履歴はユーザーごとに、すべてのキャンペーンで共通で保存されます。

![カラーメモリー](./2022.2/colour-memory.png)

(\*) 色は、ピッカーを閉じたときにリストに追加されます。描画に使用しただけでは追加されません。後者の場合、コードベース全体に手を加える必要がありますが、現在の方法ではカラーピッカーのロジック内に収めることができます。

### バグ

カラーピッカーの 2 つのバグも修正されました。

#### 不透明度のリセット

カラーバー（不透明度バーより上のバー）をクリックすると、現在の不透明度レベルを記憶する代わりに、不透明度が 1 または 0 にリセットされることがよくありました。

#### 彩度パネルが赤に戻る問題

カラーバーで最初に色を選択し、その後彩度の長方形をクリックすると、カラーバーが左端の値（赤）にリセットされることがよくありました。これはもう発生しないはずです。

## ロジックの調整

ロジックは 2022.1 リリースの新しい目玉の 1 つで、今回はその新しさをさらに磨き上げます！

### ドア：アイコンの視認性

Play モードでドアにカーソルを合わせると、<Lock /> または <Unlock /> アイコンが表示されます。
これまでこれは黒いアイコンだったため、暗い背景では見づらくなっていました。

今回のリリースではアイコンに白い枠線が追加され、常に表示されるようになりました。

### ドア：ブロッカーの指定

ドアロジックの最初のリリースは、純粋に...ドアを対象としていました。
標準のドアでは、開閉時に「ブロック移動」と「ブロック視野」のプロパティが切り替えられる必要があります。
ただし、跳ね橋などのドアの変種や窓など、1 つのプロパティだけを切り替えたい場合もあります。

クリック時にどのブロッカーを切り替えるかを指定できるようになりました。

![ドアのブロックモード](./2022.2/door-block-mode.png)

もちろん、もう一方のブロックプロパティは手動で変更することもできます。\
（例：窓にドアロジックを使って視線の切り替えだけを行い、カーテンを模倣しつつ、窓に石が投げ込まれた場合は移動プロパティを変更する）

### バグ

シェイプロジックに関連する複数のバグが修正されました。

- Draw ツールのドア権限が保存されない問題
- シェイプのプロパティを開いているときにドアロジックの切り替えが即時に UI に反映されない問題
- テレポートゾーンが他のフロアから発動する問題
- ロジック初期化のエッジケースでリフレッシュまで UI が壊れる問題
- ロジックの権限セレクターがエッジケースでエラーを表示する問題

## UI/UX の改善

特定の領域での UX と全体的な UI を改善するための変更がいくつか加えられました。

### ローディングアニメーションをより早く表示

キャンペーンを開くと、きれいなローディングアニメーションが表示されます。
ただし、このアニメーションは特定の時点から始まるため、コンピューターによっては
キャンペーンを開いたときに何も起きていないように見える短い期間がありました。

アニメーションはキャンペーンをクリックした直後に表示されるようになり、PA が何か処理を行っていることが明確になり、誤クリックしたのではと心配する必要がなくなりました。

### シェイプに応じた敗北オーバーレイとバッジのスケーリング

シェイプの敗北オーバーレイとシェイプバッジは固定サイズでした。
そのため、超巨大生物のバッジは非常に小さく、超小型生物のバッジはほぼクリーチャートークン自体を隠してしまいました。
さらに、異なるグリッドサイズを使用するとこれも崩れていました。

今回のリリースでは、これらの要素が属するシェイプのサイズに応じて適切にスケーリングされるようになりました。

### Firefox でのモーダル処理

Firefox の dragEnd イベントの処理は非常に不安定/バグが多いため、モーダルのドラッグが完全に壊れていました。
この問題の一部は Firefox の nightly バージョンで修正されていますが、私が気になっていたすべてが短期的に Firefox で修正されるわけではありません。そのため、モーダルのロジックをドロップイベントを使用するように変更しました。少しコードが増えますが、少なくともすべてのブラウザで同じ動作が保証されます。

### ビューポート

プレイヤーのアクティブなビューポート（有効時）を示す長方形は 1 色でした。ドアのアイコンと同様に、背景色によっては視認性が良くありませんでした。今回は対比用に 2 色目の色も使用します。

![ビューポート UI の更新](./2022.2/viewport.png)

### その他

- キャンペーンの削除/退出プロンプトにデフォルトの「いいえ」ボタンを表示
- ブラウザの戻る/進むボタン使用時にアセットマネージャーが UI を正しく更新
- ダッシュボードのナビゲーションヘッダーが誤ってスタイルされることがある問題

## Server 関連

サーバー側にもいくつかの変更があり、サーバー設定への変更も含まれます！

### ログのローテーション

サーバーは、1 つの巨大な終わりのないログファイルの代わりに、ログのローテーションを行うようになりました。

General セクションに 2 つの新しいプロパティが追加されました。

```python
max_log_size_in_bytes = 200_000
max_log_backups = 5
```

これらの機能の詳細については、サーバー設定内のドキュメントを確認してください。

### インポートチャンクサイズ

キャンペーンファイルは、アセットがファイルの一部であるため、大きくなる可能性があります。
アップロードサイズをセキュリティリスクになるような非常識な大きな値に設定する必要を避けるため、
クライアントはインポートファイルをサーバーが受け付ける最大サイズに一致するチャンクに分割して送信します。

このサイズは Webserver セクションで設定でき、デフォルトは 10 MiB です。

```python
max_upload_size_in_bytes = 10_485_760
```

## バグ

### SVG の修正

シェイプの Extra Settings メニューの SVG セクション専用の修正がいくつかあります。

- ExtraSettings の svg セクションがタブを切り替えるまで即時に更新されない問題
- ExtraSettings の svg 削除が正しく機能しない問題
- 既存の svg プロパティがないシェイプに対して ExtraSettings の svg 追加が機能しない問題

### Undo/Redo の修正

- リサイズ操作の Redo ロジックが、スナップされた場合に正しい位置を記憶していない問題
- Draw ツールが、無効なシェイプを undo スタックに追加する操作を作成しようとする問題
- 移動と回転で Undo/Redo がサーバーに反映されない問題

### その他

- スポーンロケーションの読み込みが間違っていた問題
- ポリゴン編集 UI で変更したポイントがリフレッシュまでスナップできない問題
- アセットソケットが過去の接続をクリーンアップしていなかった問題
- 光源であるオーラが、戦争の霧がオフのときに黒い円として表示されていた問題
- デフォルトのロケーションズームレベルが 1.0 から 0.2 に変更
