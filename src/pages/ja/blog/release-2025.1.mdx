## 削除された機能

今回のリリースでは整理を行い、2 つの機能が削除されました。

### Labels/Filters

前回・前々回のリリースノートでお知らせしたとおり、この機能群は正式に削除されました。

Labels はシェイプに付けるタグで、filter ツールを使うと、そのタグで画面内のシェイプを表示・非表示にすることができました。
この機能には今でもいくつかの用途があるとは思いますが、現在の実装はあまり良くなく、見た目も古く、私が知る限り使われていませんでした。
非推奨のお知らせを出してから誰からも連絡がなかったという事実は、削除しても誰も困らないことを示しています。

### .paa ファイル

以前のバージョンの PA では、アセットマネージャーに、すべてのアセットを `.paa` ファイルにエクスポートし、別の PA インストールでインポートできるオプションがありました。

その後、アセットマネージャーはリワークされ、UI からこの機能がなくなりました。
当初はこの機能を復活させるつもりでしたが、その間にキャンペーンのエクスポート機能が追加され、関連するすべてのアセットが自動でエクスポートされるようになりました。

これで元の `.paa` の用途のほとんどをカバーできます。先ほどの削除と同様、UI からこの機能がなくなったことについて誰からも質問がありませんでした。
また、内部のアセットロジックの一部が、後述の変更のために書き直されているため、整理する良い機会でした。

## 3D ダイスシミュレーションの調整

_rexy712 氏によるコントリビューション_

3D ダイスの物理的特性に変更が加えられ、より良い動作になるはずです。
特に、ダイスが止まるまでの時間が大幅に短くなります。

## D100 の処理

D100 ロールの処理は 2D モードと 3D モードで大きく異なり、2D モードは 1〜100 のすべての値をカバーしていました。
一方、3D モードは十の位のみ（例：10/20/30...）で、一の位をカバーするには追加の d10 を投げる必要がありました。
しかし、たとえば 00 と 0 が出た場合にどうなるべきかを処理するロジックはありませんでした。

今回のリリースでは上記すべてが改善されます。3D モードで d100 を投げると、自動的に d10 も一緒に投げられるため、
自分で指定する必要はありません。さらに、00/0 の場合の動作を定める組み込みのロジックも用意されています。

内部のダイスライブラリ `@planarally/dice` は、0〜99 モードか 1〜100 モードのどちらかに設定できます。
ただし、現在の PlanarAlly のインターフェースにはこれを設定する方法がないため、当面は常に 1〜100 モードが選択されます。

## アセット

今回の大きな変更のもう 1 つはアセット関連です。サーバー側の技術的な変更に加え、クライアント側のビジュアルも更新されました！

### DM のゲーム内 UI

アセットマネージャーは、セッションの準備のためにゲーム外でアセットを整理するのに便利な方法です。

一方、ゲーム内では DM のアセットの見え方がまったく異なります。
ツリー構造のサイドバーがありますが、特定のアセットをマップにドラッグする以外に実際の操作はできませんでした。

今回のリリースではこれを変更し、サイドバーを廃止して、新しいノート UI に似た大きなモーダルに置き換えました。
見た目や操作感はゲーム外のアセットマネージャーと同様です。
実際、ゲーム外とゲーム内のアセットマネージャーは、UI のかなりの部分で同じコードを共有するようになりました。

昨年のノート UI のリワークと同様、アセット UI はサイドバーから開けるほか、ショートカットキー <kbd>a</kbd> でも開けます。

![新しいアセット UI](./2025.1/asset-ui.png)

#### 検索

サイドバーには常に検索バーがありましたが、新しい UI でも引き続き利用でき、より効率的に実装されています。
ゲームに接続したときにすべてのアセット情報を事前に読み込む必要がなくなりました。

検索結果の表示方法がまったく異なるため、その動作はサイドバーの検索とは少し異なります。
新しい UI は検索に一致するすべてのアセットを直接表示します。一方、サイドバーは、どこかに一致するアセットを含むすべてのフォルダーを表示したままにしていました。

#### ショートカット

もう 1 つの新機能は、フォルダーをショートカットとして登録できることです。ショートカットは左側の、常設ショートカット「All assets」の下に表示されます。
頻繁に必要になる特定のフォルダー（例：メインのキャンペーンフォルダー、よく使う D&D トークンなど）にすばやく移動できるようになります。

ショートカットはキャンペーンごとに保存されます。

#### ドラッグ

新しい UI は画面中央のかなりの部分を占めるため、どのようにしてアセットをマップにドラッグするのか疑問に思われるかもしれません。

アセットのドラッグを開始すると、アセットマネージャーと同様に、フォルダーの上にドラッグしてそのフォルダーに移動できます。
ただし、アセットを UI の外にドラッグすると UI が完全に消え、実際にマップ上に配置できるようになります。

わかりやすくするため、ドラッグ中は常にこの動作を説明するメッセージが UI の下部に表示されます。

### アセットマネージャーの細かな変更

#### 名前変更 UI

_rexy712 氏によるコントリビューション_

アセットの名前を変更するには、新しい名前を入力するポップアップが開かれていました。
これは、OS のファイルエクスプローラーでの操作に慣れたように、その場で名前を編集できるようにすることで、より控えめになりました。

#### コンテキストメニューの選択

アセットマネージャーでアセットを右クリックするとコンテキストメニューが表示されます。
これまでは常に、右クリックしたアセットだけが選択されるようになっていました。

これは解消され、複数のファイルを選択してコンテキストメニューから削除できるようになりました。
複数のアセットが選択されている場合、「rename」などのアクションは表示されません。

なお、選択していないアセットをクリックした場合は、従来どおりそのアセットだけが選択されます。

### サムネイル

アセットはさまざまな品質でアップロードでき、マップに表示するときは同じ品質であることが望まれます。

しかし、高品質が不要で単にデータが重くなるだけの場面もあります。
アセットマネージャーは、一度に多くの画像を読み込む可能性がある主な場所です。

今回のリリース以降、サーバーはアップロードされたすべてのアセットのサムネイルを生成しようとし、アセットマネージャーなどでアセットを表示する際にサムネイルを優先して使用します。
これにより、多数の高品質画像を読み込む必要がなくなり、アセットマネージャーの読み込みがはるかに高速になります。

<Warning title="サーバーアップグレード">
    サーバーを起動すると、既存のすべてのアセットのサムネイルを生成するバックグラウンドジョブが開始されます。これは
    時々処理のログを出力しますが、それ以外はメインのサーバー動作をブロックしません。

    サムネイルが存在しない場合のフォールバック動作もあるため、この処理の重要性は低めです。

</Warning>

### アップロードと保存容量の制限

サーバー所有者は、サーバー設定でアセットの上限をグローバルに設定できるようになりました。
新しい設定が 2 つ用意されています。1 つは単一アセットの最大サイズを制限するもので、もう 1 つは特定ユーザーがサーバー上に持つ全アセットの合計サイズを制限するものです。

どちらの設定もデフォルトでは無制限なので、必要に応じて変更してください。

制限の変更は新しくアップロードされるアセットにのみ適用される点に注意してください。
設定が追加される前にユーザーがより多くの容量を使っていた場合、既存のアセットは削除されませんが、それ以上アップロードできなくなります。

<Warning title="サーバーアップグレード">
    これにより設定ファイルに新しいエントリが追加されます。設定に追加しないとサーバーが起動できなくなるため、必ず追加してください。
</Warning>

### 保存場所

_これは技術的なサーバー変更のため、プレイヤーの方は読み飛ばしていただいて構いません_

アップロードされたアセットに関連する物理ファイルは、特定のフォルダーに保存され、ファイル名はすべてアセットのハッシュと等しくなります。
これまでは 1 つのフラットなフォルダーに保存されていましたが、パフォーマンス上の理由から、今回のリリースではハッシュに基づくサブフォルダー構造で保存されます。
これにより、1 つの大きなフォルダーで操作する必要がなくなり、一部の I/O 操作時間が短縮されます。

<Warning title="サーバーアップグレード">
    起動時に、既存のすべてのファイルを新しい場所に移動する 1 回限りの移行が行われます。
    サーバー上のアセットの量によっては、時間がかかる場合があります。

    物理ファイルの移動と、すべてをリンクするデータベース内のデータの移動の両方が行われるため、
    この処理を中断しないことが重要です。

</Warning>

## ノート

最後の変更はノート関連です。ただし、そのほとんどは小さな変更とバグ修正です。

### 完全なポップアウト

新しいノート UI の導入により、ノートマネージャーからノートをポップアウトして、PA 画面内をドラッグできる浮遊ノートモーダルにすることができます。

今回のリリースでは、このモーダルをページから完全にポップアウトできるようになり、ノートを別の画面にドラッグして操作を続けられるようになりました。
この浮遊ダイアログは開いている PA ページに紐付いていますが、特定の画面位置には拘束されません。PA のタブを閉じると、浮遊ダイアログも閉じます。

### グローバルノートへのアクセス

グローバルノートへのデフォルトアクセスが削除されました。
これまでユーザーはノートを全ユーザーにグローバルに表示（または編集）できるように設定できましたが、これは望ましいことではありません。

### 小さな UI 改善

- ノートの検索バーをボタンでクリアできるようになりました。
- ローカル/グローバルの切り替えが、全ノートをフィルタリングできるドロップダウンになりました。
- サイドバーのノートボタンがプレイヤーにも表示されるようになりました。
- 書き込み権限のないノートのポップアウトで、表示が「Edit」ではなく「View source」になりました。

### 修正

- 閲覧のみのアクセスに関するさまざまな UI バグが修正されました
- ノートのページネーションが、検索/フィルターを変更してもリセットされなかった問題を修正
- ノートのデフォルト編集アクセスが正しく機能していなかった問題を修正
- 検索バー UI が他の UI と重なっていた問題を修正
- 読み取り専用ノートをローカルで編集できた問題を修正（これらの変更は常にサーバー側で拒否されていました）

## Draw ツールのデフォルトカラー

戦争の霧レイヤーに描画するとき、壁、窓、ドアなどを描き分けることがよくあります。
それぞれに特定の色を使うことで、戦争の霧レイヤーを開いたときにすぐ視覚的に区別できるようにしています。

これまでは種類を切り替えるたびに色を変更する必要があり、色ツールに最近使った色の履歴があるとはいえ、面倒でした。

今回のリリースではデフォルトカラーが追加され、クライアント設定で壁、窓、ドアのデフォルトカラーを設定できるようになりました。
これらは Draw ツールで該当する場面にデフォルトで適用されます。

これを明確に伝えるため、デフォルトカラーが使用される場合、Draw ツールのカラーピッカーは無効になります。
ただし、Draw ツールの vision 設定（2 つ目のタブ）で「デフォルトカラーを使用」チェックボックスを外せば、この動作を無効にして特定のオブジェクトに個別の色を選ぶこともできます。

小さな追加ですが、私の時間を大幅に節約してくれました！
