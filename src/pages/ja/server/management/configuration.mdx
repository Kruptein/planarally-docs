# サーバー設定

<Warning title="最近の変更">
    サーバー設定はリリース 2025.2 で完全に変更されました。このドキュメントで説明している設定は新しい形式のものです。
</Warning>

デフォルトでは、設定ファイルは**存在しません**。代わりに PA はすべての設定にデフォルト値を使用します。デフォルトの設定値は[こちら](#default-config)で確認できます。

動作を変更するには、サーバーの `data` フォルダーに `config.toml` ファイルを作成してください。

部分的な設定ファイルが指定された場合、不足しているフィールド/セクションには、該当する場合デフォルト値が使用されます。

# 形式

設定ファイルの拡張子が示すように、設定は [TOML](https://toml.io/en/) でフォーマットされています。

設定は、`[section]` ヘッダーを持つ小さなセクションに分割され、サブセクションは `[section.some.subsection]` で示されます。
各(サブ)セクションの後には、特定の値を設定するための個別の行が続きます。

TOML 形式の仕組みの詳細はこのドキュメントの範囲外ですが、デフォルト設定を確認すればその仕組みを十分に理解できるはずです。

# デフォルト設定

```toml
[general]
save_file = "data/planar.sqlite"
allow_signups = true
enable_export = true

[assets]
max_single_asset_size_in_bytes = 0
max_total_asset_size_in_bytes = 0

[webserver]
max_upload_size_in_bytes = 10485760

[webserver.connection]
type = "hostport"
host = "0.0.0.0"
port = 8000

[[logging]]
mode = "stdout"
level = "INFO"
```

<Info title="ファイルパス">
    ファイルやフォルダーへのパスを指定する場合、絶対パス(例:`/home/user/example.txt`)または相対パス(例:`data/planar.sqlite`)を使用できます。相対パスを使用する場合、そのパスはメインのサーバーフォルダーを基準としたものになり、設定ファイルがあるフォルダーを基準には**なりません**。
</Info>

# 重要な設定

ぜひ確認しておきたい設定は次のとおりです:

- [保存ファイルの設定](#field-save_file)
- [管理者ユーザー](#field-admin_user)
- [webserver.connection サブセクション全体](#subsection-connection)
- [CORS](#field-cors_allowed_origins)

[クライアント URL](#field-client_url)も通常は設定しておきたい項目ですが、必須ではありません。

# セクション

ここでは、考えられるすべてのオプションをデフォルト値とともに列挙します。
この情報が古くなってエラーの原因になる場合は、[GitHub](https://github.com/Kruptein/PlanarAlly/blob/dev/server/src/config/types.py)にコード形式でソースを確認できます。

## 一般

セクション名: `general`

### フィールド: `save_file`

デフォルト: `"data/planar.sqlite"`\
タイプ: `string`

保存ファイルへのパス。変更すると大きな影響がある重要な設定です。保存ファイルは適切にバックアップする必要があります[^1]。

サーバーが起動して、選択したパスが存在しない場合、サーバーは新しい保存ファイルを作成します。

<Info title="保存ファイルの形式">
    現時点では、PlanarAlly は保存ファイルの sqlite 形式のみをサポートしていることに注意してください。
</Info>

<Warning>
    サーバーの実行中に、追加のデータベースファイル(例:`planar.sqlite-shm` と `planar.sqlite-wal`)が作成されることがあります。
    `planar.sqlite-wal`(ライトアヘッドログ)ファイルは保存データベースに不可欠で、保存しないとデータが失われます。
    `planar.sqlite-shm`(共有メモリ)ファイルは重要ではなく、バックアップの必要はありません。

    サーバーが正常にシャットダウンすると、これらのファイルは消えます。ただし、サーバーがきれいに停止できなかった場合は残っていることがあります。
    保存ファイルをコピーするときは、これらのファイルが存在する場合は一緒にコピーしてください。そうしないと、保存データが破損したり古くなったりする可能性があります。

</Warning>

### フィールド: `admin_user`

デフォルト: N/A - 任意項目\
タイプ: `string`

ここにユーザー名を指定すると、そのユーザーがメインの管理者ユーザーとして扱われます。
ダッシュボードで、サーバー上のユーザーやキャンペーンなどを管理するための追加機能にアクセスできるようになります。

### フィールド: `client_url`

デフォルト: N/A - 任意項目\
タイプ: `string`\
_このフィールドの設定は一般的に推奨されますが、最小構成では必須ではありません。_

設定する場合、これはフロントエンドアプリケーションの完全なベース URL を指定します(例:"https://app.planarally.io")。

これは招待 URL とパスワード再設定メールで使用されます。未設定の場合、招待 URL は生成時にブラウザの現在の URL を参照します。ただし、メール内の URL にはルート URL の情報は含まれ**ません**。サーバーはそれを予測できないためです。

### フィールド: `allow_signups`

デフォルト: `true`\
タイプ: `boolean`

この設定は、ユーザーがフロントエンドから新しいアカウントを登録できるかどうかを決定します。無効にすると、アカウントの作成はデータベース操作でのみ可能になります。

### フィールド: `enable_export`

デフォルト: `true`\
タイプ: `boolean`

この設定が有効な場合、ユーザーはアカウントのエクスポート**および**インポートを使用できます。

これは一般的に推奨されます。ユーザーがデータを別のサーバーに移行できるようになり、またデバッグ用のデータを提供してもらえるためです。

## Webserver

セクション名: `webserver`

設定すべき最も重要なセクションの 1 つが webserver です。
ここには重要な `connection` サブセクションが含まれており、PA サーバーが外部にどのようにバインドされるかを設定します。

<div id="subsection">

### サブセクション: `connection`

_これはサブセクションです(設定方法の例は[デフォルト設定](#default-config)を参照してください)。_

これはサーバーがネットワークスタックにどのように接続するかを設定します。HostPort 構成またはソケット構成のいずれかである必要があります。
デフォルトでは HostPort の組み合わせが使用されます。

#### フィールド: `type`

デフォルト: `"hostport"`\
タイプ: `"hostport" または "socket"`

type フィールドは、最終的にどの接続タイプを使用するかを決定します。

```toml
# Either a hostport connection is configured
[webserver.connection]
type = "hostport"
...

# Or a socket connection
[webserver.connection]
type = "socket"
...
```

#### HostPort フィールド

#### フィールド: `host`

デフォルト: `"0.0.0.0"`\
タイプ: `string`

サーバーがバインドを試みる IP アドレス。

#### フィールド: `port`

デフォルト: `8000`\
タイプ: `integer`

サーバーがバインドを試みるポート。

使用するポートが他のアプリケーションで使用されていないことを確認してください。
また、使用するポートがマシンの外部からもアクセスできることを確認してください。
特にプライベートネットワーク(例:自宅)内で実行する場合、ルーターの設定で*ポート転送*を有効にする必要があるかもしれません。

#### HostPort 設定の例

```toml
[webserver.connection]
type = "hostport"
host = "192.168.0.1"
port = "80"
```

#### Socket フィールド

#### フィールド: `socket`

デフォルト: N/A\
タイプ: `string`

バインドに使用するソケットへのパス。

#### Socket 設定の例

```toml
[webserver.connection]
type = "socket"
socket = "/var/run/pa.sock"
```

</div>

<div id="subsection">

### サブセクション: ssl

これは任意のサブセクションで、省略した場合、PA サーバー自体には SSL 設定は適用されません。
これはチェーンの上位(例:リバースプロキシ)で SSL を設定することを妨げるものではありません。

チェーンのどこかで SSL を設定することを強くお勧めします!

#### フィールド: `enabled`

デフォルト: `false`\
タイプ: `boolean`

SSL セクションを完全に削除したりコメントアウトしたりせずに、SSL 設定を有効/無効にできます。
この値が `true` に設定されている場合にのみ、SSL 設定が実際に適用されます。

#### フィールド: `fullchain`

デフォルト: N/A\
タイプ: `string`

フルチェーン証明書へのパス。

#### フィールド: `privkey`

デフォルト: N/A\
タイプ: `string`

秘密鍵証明書へのパス。

#### SSL 設定の例

```toml
[webserver.ssl]
enabled = true
fullchain = "/etc/letsencrypt/live/planarally/fullchain.pem"
privkey = "/etc/letsencrypt/live/planarally/privkey.pem"
```

</div>

### フィールド: `cors_allowed_origins`

デフォルト: N/A (任意項目)\
タイプ: `string / List of strings`

WebSocket サーバー用の CORS 設定。

この値は socketio サーバーに渡されます。詳細は [socketio](https://python-socketio.readthedocs.io/en/latest/api.html#asyncserver-class) のドキュメントを参照してください。
すべてのオリジンを許可するには `'*'` を設定できます。これはテスト目的には便利ですが、安全ではありません。

これは多くの場合、ワイルドカード値(\*)または正しい特定のドメインのいずれかに設定しないと動作しません!
サーバーコンソールには、CORS が原因で接続が拒否されたときにログが出力されます。

### フィールド: `max_upload_size_in_bytes`

デフォルト: `10_586_760` (10 \* 1024 \*\* 2 == 10 MB)\
タイプ: `integer`

クライアントからの 1 回のデータアップロードの最大サイズ。

これは主にチャンク化の戦略として機能することに注意してください。
アセットのアップロードとキャンペーンの転送はこの最大値に基づいてチャンク化されますが、その合計サイズは制限を超える可能性があります!
ユーザーのアセットサイズを制限する方法については、設定の assets セクションを参照してください。

## メール

セクション名: `mail`

これは任意のセクションで、デフォルトでは有効になっていません。

現在は、パスワード再設定フローの一部としてメールを送信するためにのみ使用されます。

### フィールド: `enabled`

デフォルト: `false`\
タイプ: `boolean`

メールセクションを完全に削除したりコメントアウトしたりせずに、メール設定を有効/無効にできます。
この値が `true` に設定されている場合にのみ、メール設定が実際に適用されます。

### フィールド: `host`

デフォルト: N/A\
タイプ: `string`

SMTP メールサーバーのホスト。必ず入力してください。

### フィールド: `port`

デフォルト: N/A\
タイプ: `integer`

SMTP メールサーバーのポート。必ず入力してください。

### フィールド: `username`

デフォルト: N/A (任意)\
タイプ: `string`

該当する場合、認証に使用するユーザー名を指定できます。

### フィールド: `password`

デフォルト: N/A (任意)\
タイプ: `string`

該当する場合、認証に使用するパスワードを指定できます。

### フィールド: `default_from_address`

デフォルト: N/A\
タイプ: `email-string`

メール送信時に使用するデフォルトの送信元メールアドレス。

### フィールド: `ssl_mode`

デフォルト: `"starttls"`\
タイプ: `Literal["ssl", "tls", "starttls", "lmtp"]`\
追加: v2025.2.1

使用するクライアント接続モードを設定します。
デフォルトでは starttls メソッドが使用され、幅広い環境をカバーできます。

これは正しく動作しない場合があり、その場合は `"ssl"` モードや他のモードを試すことができます。

## 統計

セクション名: `stats`

これは任意のセクションで、指定しない場合はデフォルトの値セットが使用されます。
匿名の利用統計情報の収集と送信を制御します。

何を、なぜ収集するかについての情報は、[この GitHub PR](https://github.com/Kruptein/PlanarAlly/pull/1608) を参照してください。

### フィールド: `enabled`

デフォルト: `true`\
タイプ: `boolean`

統計情報セクションを完全に削除したりコメントアウトしたりせずに、統計情報の収集を有効/無効にできます。
`false` に設定すると、統計情報の収集は一切行われません。

### フィールド: `enable_export`

デフォルト: `true`\
タイプ: `boolean`

PA 統計サーバーへの統計情報のエクスポートを無効にできます。
ローカルでの収集は引き続き行われます。

### フィールド: `export_frequency_in_seconds`

デフォルト: `24 * 60 * 60` (1 日)\
タイプ: `int`

統計情報が PA 統計サーバーに送信される頻度を決定します。

これを 1 日より短くすることはお勧めしません。
推奨される頻度は 1 日、1 週間、または 1 か月です。

### フィールド: `stats_url`

デフォルト: `https://stats.planarally.io`\
タイプ: `string`

統計データの受信 URL。

## ロギング

セクション名: `logging`

これは任意のセクションで、デフォルトの設定では "INFO" レベルで標準出力にログを出力します。

<Info title="複数のエントリ">
    ロギングセクションは、複数の出力ファイルを設定するために複数回指定できます。そのため、セクションヘッダーは
    `[[logging]]` として入力する必要があります。
</Info>

### フィールド: `level`

デフォルト: `INFO`\
タイプ: `Literal["DEBUG", "INFO", "WARNING", "ERROR", "CRITICAL"]`

このロガーが出力するレベル。これより上のレベルもこのレベルに記録されます。たとえば ERROR に設定すると、ERROR と CRITICAL の両方がこの出力に記録されます。

### フィールド: `mode`

タイプ: `Literal["stdout", "file"]`

stdout を指定した場合、利用できる他のフィールドは level だけです。

標準出力を critical に設定するロギングの例を次に示します。

```toml
...
[[logging]]
mode = "stdout"
level = "CRITICAL"
...
```

### フィールド: `file_path`

デフォルト: `data/planarally.log`\
タイプ: `string`

ファイルベースのログの出力パスを設定します。docker を使用する場合は、コンテナの外でも利用できるように data フォルダーを使うことをお勧めします。

### フィールド: `max_log_size_in_bytes`

デフォルト: `200_000`\
タイプ: `int`

ログファイルが次のファイルにローテーションされるまでの最大サイズ。

### フィールド: `max_log_backups`

デフォルト: `5`\
タイプ: `int`

保持するバックアップファイルの数。古いファイルは自動的に削除されます。

バックアップファイルを 2 つだけ持つファイルロガーの設定例を次に示します。これは標準出力の例と組み合わせて、標準出力とファイルの両方に出力することもできます。

```toml
...
[[logging]]
mode = "file"
level = "INFO"
max_log_backups = 2
...
```

## アセット

セクション名: `assets`

これは任意のセクションです。

### フィールド: `max_single_asset_size_in_bytes`

デフォルト: `0`\
タイプ: `int`

新しくアップロードされる 1 つのアセットの最大サイズ(バイト)。
このフィールドが `<= 0` の場合、「制限なし」とみなされます。

これは新しいアセットのアップロードにのみ影響することに注意してください。値を変更しても既存のアセットには影響しません。

### フィールド: `max_total_asset_size_in_bytes`

デフォルト: `0`\
タイプ: `int`

ユーザーがアップロードできる合計サイズの上限(バイト)。
このフィールドが `<= 0` の場合、「制限なし」とみなされます。

アセットのサイズが原因でユーザーに許可された合計を超える場合、そのアセットは拒否されます。
これは新しいアセットのアップロードにのみ影響することに注意してください。値を変更しても既存のアセットには影響しません。

[^1]: SQLite のドキュメントでは、[-wal](https://www.sqlite.org/tempfiles.html#write_ahead_log_wal_files) ファイルと [-shm](https://www.sqlite.org/tempfiles.html#shared_memory_files) ファイルの重要性が説明されています。
