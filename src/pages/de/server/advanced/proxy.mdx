# Reverse-Proxy

Üblicherweise verwendet man beim Hosten eines Servers einen Reverse-Proxy, um den eigentlichen Server vor der Außenwelt abzuschirmen.
Diese Seite bietet eine Reihe von Beispielen für einige beliebte Proxys. Beachte, dass einige davon von der Community beigesteuert und nicht vom PA-Autor getestet/verifiziert wurden.

Beachte, dass PA entweder im `host:port`-Modus oder im Socket-Modus laufen kann. Die meisten Proxys können beides verarbeiten; die Beispiele verwenden in der Regel eine der beiden Varianten.

Ein letzter Hinweis: Die meisten Beispiele enthalten hartkodierte Dinge, die du ändern musst. (z. B. wird "app.planarally.io" als Beispiel-Hostname verwendet).

<Warning title="Websocket">
PA ist im Allgemeinen ein ganz normaler Webserver, benötigt aber Websocket-Verbindungen.
Je nach Proxy kann dies etwas mehr Einrichtung erfordern.

Wenn du die Hauptseite von PA aufrufen kannst, aber keine Assets hochladen oder im Spiel nichts Nützliches tun kannst, ist die Verbindung zum Websocket höchstwahrscheinlich das Problem.
Entweder ist deine Proxy-Konfiguration fehlerhaft oder du hast CORS-Probleme. Für letzteres überprüfe noch einmal, ob die [CORS-Konfigurationseinstellung](/de/server/management/configuration/#field-cors_allowed_origins) korrekt konfiguriert ist.

</Warning>

## Caddy

Alles, was du brauchst, ist dies:

_Geht davon aus, dass der PA-Socket unter `/run/pa.sock` liegt. (das ist nur ein Beispiel)_

```apache
app.planarally.io {
  handle {
    reverse_proxy unix//run/pa.sock
  }
}
```

Caddy übernimmt die Websocket-Angelegenheiten automatisch.
Es erstellt auch Letsencrypt-Zertifikate out of the box.

## Nginx

Bei der Verwendung von nginx musst du die Websocket-Weiterleitung explizit einrichten.

Im Folgenden findest du eine Beispielkonfiguration, die meine alte Konfiguration nachahmt (bevor ich zu caddy gewechselt bin).
Der wichtige Teil ist, dass die Sockets durchgereicht werden.

Dies verwendet ein Socket-Setup. Wenn du eine host:port-Kombination verwendest, lasse den upstream-Abschnitt weg und trage sie direkt in proxy_pass ein.

```nginx
server {
    listen *:443;
    ssl on;
    ssl_certificate /etc/letsencrypt/live/planarally.io/fullchain.pem; # managed by Certbot
    ssl_certificate_key /etc/letsencrypt/live/planarally.io/privkey.pem; # managed by Certbot

    server_name app.planarally.io;

    location / {
      proxy_set_header Host $http_host;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      proxy_redirect off;
      proxy_buffering off;
      proxy_pass http://pa_sock;
    }

    location /socket.io/ {
      proxy_http_version 1.1;
      proxy_set_header Upgrade $http_upgrade;
      proxy_set_header Connection "Upgrade";
      proxy_set_header Host $host;
      proxy_pass http://pa_sock/socket.io/;
    }

    location /static {
      alias /home/darragh/dev/planarally/server/;
    }

    location ~ /.well-known {
      allow all;
      root /var/www/letsencrypt;
    }
}

upstream pa_sock {
  server unix:/tmp/planarally.sock fail_timeout=0;
}
```

## Apache

Die folgende Apache-Konfiguration erwartet, dass der PlanarAlly-Anwendungsserver auf Port 8008 auf demselben Rechner wie der Proxy läuft.
Sie geht davon aus, dass du SSL/TLS-Zertifikate und private Schlüssel an den in `SSLCertificateFile/SSLCertificateKeyFile` angegebenen Orten erzeugt hast.
Alle HTTP-Anfragen werden zu HTTPS umgeleitet.
Ersetze `planarally.CHANGEME.org` durch den tatsächlichen Domainnamen, unter dem PlanarAlly verfügbar sein wird.

```apache
<VirtualHost *:80>
    ServerName planarally.CHANGEME.org
    # Redirect all HTTP requests to HTTPS
    RewriteEngine On
    RewriteCond %{HTTPS} off
    RewriteRule (.*) https://%{HTTP_HOST}%{REQUEST_URI}
</VirtualHost>

<VirtualHost *:443>
  ServerName  planarally.CHANGEME.org
  SSLEngine on
  SSLCertificateFile /etc/ssl/certs/planarally.CHANGEME.org.crt
  SSLCertificateKeyFile /etc/ssl/private/planarally.CHANGEME.org.key
  ProxyPreserveHost On
  ProxyRequests off
  ProxyPass / http://127.0.0.1:8008/
  ProxyPassReverse / http://127.0.0.1:8008/
  RewriteEngine on
  RewriteCond %{HTTP:Upgrade} websocket [NC]
  RewriteCond %{HTTP:Connection} upgrade [NC]
  RewriteRule ^/?(.*) "ws://127.0.0.1:8008/$1" [P,L]
</VirtualHost>
```

## Traefik

Hier ist eine Beispielkonfiguration mit [docker-compose](https://docs.docker.com/compose/) und
[traefik](https://containo.us/traefik/), einem Docker-Reverse-Proxy-Manager. Es wird davon ausgegangen, dass dein
Traefik-externes Netzwerk ebenfalls `web` heißt.

#### docker-compose.yml

Es ist wichtig, die Änderungen an `domain.com` zu beachten, damit sie zu deiner Domain passen, sowie die Pfade zu sowohl
den `assets`- als auch den `data`-Ordnern. Diese Volumes können sein, was auch immer du möchtest.

```yaml
---
version: "3"

networks:
    traefik_network:
        external:
            name: web

services:
    # Media Server
    planarally:
        image: kruptein/planarally:latest
        restart: unless-stopped
        networks:
            - traefik_network
        volumes:
            - "/path/to/data:/planarally/data/"
            - "/path/to/assets:/planarally/static/assets/"
        labels:
            - "traefik.http.services.pa.loadbalancer.server.scheme=http"
            - "traefik.http.services.pa.loadbalancer.server.port=8000"
            - "traefik.enable=true"
            - "traefik.docker.network=web"
            - "traefik.http.routers.pa-http.service=pa"
            - "traefik.http.routers.pa-http.rule=Host(`pa.domain.com`)"
            - "traefik.http.routers.pa-http.entrypoints=http"
            - "traefik.http.routers.pa.service=pa"
            - "traefik.http.routers.pa.rule=Host(`pa.domain.com`)"
            - "traefik.http.routers.pa.entrypoints=https"
            - "traefik.http.routers.pa.tls=true"
            - "traefik.http.routers.pa.tls.certresolver=dns"
            - "traefik.http.routers.pa.tls.domains[0].main=domain.com"
            - "traefik.http.routers.pa.tls.domains[0].sans=*.domain.com"
            - "traefik.http.middlewares.sslheader.headers.customrequestheaders.X-Forwarded-Proto=https"
            # these are required, this forces the websocket to forward over https
            - "traefik.http.routers.pa.middlewares=ssl-header"
            - "traefik.http.middlewares.ssl-header.headers.customrequestheaders.X-Forwarded-Proto=https"
```
