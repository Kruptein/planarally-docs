距离上一个版本发布已经有一段时间了。好消息是，报告的 bug 很少，0.26 版本相当稳定，这总是让人欣慰。坏消息是，这个版本可能会有些波折，我们很快会看到原因。

这个版本的主要目标只有一件事：把 PA 使用的响应式框架（Vue）从版本 2 升级到版本 3。这是一个非常技术性的更改，*理想情况*下不会直接影响用户体验，但它涉及大量代码，所以我想用更长的时间来验证一切是否正常。我会在文章末尾详细介绍这些更改的内容，以免吓跑真正的用户！ :)

但内部代码更改并不是唯一的改动。先攻功能得到了全面重构，把 PA 用作实体游戏桌面也有了一些新功能，社区又一次贡献了一些精彩的内容。那我们就开始吧！

## 先攻

到目前为止，先攻工具基本是在 reddit 上有人评论询问先攻支持后，几天内仓促拼凑出来的。它能完成工作，但一直有一些小问题。我终于抽出时间来解决这些遗留问题，并重新思考了先攻的部分功能。

![先攻工具重构](./0.27/initiative.png)

### UI/UX

其中一个问题是 UI 可能非常拥挤。尤其是对那些总是能看到管理按钮却无法以任何方式操作的玩家来说。

#### DM 工具栏

仅限 DM 的操作已被移到一个独立的“DM 工具栏”中，只对（联合）DM 可见。

#### 设置

此外，相机和视野锁定图标已移到客户端设置中，可以通过一个小齿轮图标访问。这也解决了那个“bug”——以前经常使用这些设置的人总是需要重新应用这些配置。

#### 移除

另一个明显的变化是，每个先攻行动者的图标中不再有垃圾桶。对于一件不需要*时刻*看到的东西来说，它占了一些空间。现在，悬停到某个先攻行动者上时，右上角会出现一个小红叉。

#### 输入框

最后，输入值本身获得了更宽的宽度。现在它终于有空间呼吸了！它的样式也发生了变化，不再是一个突兀的奇怪输入框，而是看起来像模态框里的一个“普通”元素。

在输入先攻值时，如果其他人同时在修改数值，你可能会失去输入框的焦点，导致先攻值跳来跳去。过去这个问题通过“等到你提交更改后再刷新先攻窗口”来解决。但如果你仍然聚焦在输入框上，没有任何提示表明数值尚未同步。这并不理想，因为很不清楚，可能会造成很多困惑。因此，在新的先攻窗口中，当你聚焦在输入框上时，所有其他先攻行都会被模糊处理，以直观地显示你正在进行一个尚未完成的操作。

![先攻模糊](./0.27/blur.png)

作为最后的体验优化，在先攻输入框中按 `enter` 现在也能生效了 :)

### 行为

旧版先攻的第二个问题是排序行为可能会卡住，先攻顺序不再更新或错误更新。背后负责这一点的数据结构已经更改，现在应该始终表现正常。

先攻的 DM 工具栏也有一些新功能：

现在你可以回到之前的行动，如果你不小心跳过了某人，或者某人的回合还没结束。你现在还可以清除所有先攻值。这样你就可以重新进行先攻检定，看看还有谁需要更新数值，否则你可能无法确定某个数值是新是旧。

#### 排序

最后，你现在还可以主动更改排序行为。三个选项分别是：降序、升序和手动。如果你拖拽先攻，排序会自动切换为手动模式，除非你交换的两个行动者具有相同的先攻值。

## 复制地点

_贡献者：CalebKoch_

这个巧妙的功能允许 DM 把地点复制到另一个会话。概念非常简单，但如果你在为多个队伍运行同一个战役，而且不必重新绘制整个地图和战争迷雾，就能省下大量工作！

DM 可以从要复制来源的地点设置中访问此功能。对话框会显示你拥有的所有战役。

## 游戏桌面

这部分来自于 Last Gameboard 那边的请求，我一直与他们合作，把 PA 带到他们的平台上，不过它也有普遍用途！

![实体游戏桌面尺寸](./0.27/gameboard.png)

大多数情况下，PA 纯粹被用作桌面游戏的数字解决方案。在这种情境下，最重要的首先是每个网格单元格应代表的像素尺寸。

在某些情况下，PA 被用作“传统”实体游玩的延伸，因此 PA 被当作带有额外功能的更传统的游戏桌面来使用。在这种情境下，直接填写像素尺寸就没那么有意思了，能够把模型小人放到桌面上才是重点。

现在，你可以通过提供模型小人的尺寸和屏幕的 PPI（有时称为 DPI）来定义实体情境下的网格尺寸。这样一来，缩放就失去了意义，所以目前缩放功能暂时不可用。

## 视口

作为 DM，你有时有自己的 DM 屏幕，但同时还要控制另一台显示玩家视角的屏幕。在这种情况下，切换屏幕/设备来控制玩家的相机有时很麻烦。

这个版本的新增功能是可以显示玩家的活动视口。在管理员设置中，你可以为单个玩家开启视口。

每个视口都会在 DM 图层上渲染为一个无填充的矩形，其边框显示该玩家当时正在观看的确切区域。

DM 还可以拖动每个视口，直接平移对应玩家的屏幕。

## 体验优化

以上就是大部分较大的改动，不过还做了许多不错的体验优化！

### 素材菜单同步

素材菜单侧边栏（目前仅对 DM 可用）在素材管理器添加新素材时从来不会实时更新。这让我和许多其他人每次都不得不添加新素材后重新加载页面，非常痛苦。

我们不再需要忍受这一点，因为侧边栏现在会随着素材管理器的变化实时更新！

### 编辑形状文本值

某些形状（例如 Text 和 CircularToken）带有特定的文本值。在过去，这个值只能在创建这些形状时配置，之后无法修改。

这些形状的编辑对话框的属性选项卡中新增了一行 “value”。

### HiDPI/Retina

你可能在之前的图片中看到，客户端设置中新增了一个显示选项卡。它还包含一个开关，可以开启对 HiDPI 和 retina 屏幕的支持。这应该会让一切都更清晰！

**警告**：

- 这会增加你电脑的绘制负担
- 我收到过一些报告，说启用此设置后缩放/平移会出错，所以要小心！

### ctrl 取消选中

按住 Ctrl 点击形状可以将单个形状添加到当前选中的选区中。其他工具通常也支持按住 Ctrl 点击已选中的形状来取消选中。现在这里也支持了。

### 踢出玩家确认

现在踢出玩家之前会先请求确认 :)

## 服务器

### API 服务器现在默认禁用

API 服务器是一个非常小众的功能，而且默认启用，这要求额外开放一个端口。现在它默认被禁用了，以防止那些只开放主端口运行容器的人遇到晦涩难懂的错误消息。

### public_name 默认注释掉

_贡献者：dthv_

一个小的体验优化，让人清楚这是可选功能。

### Dockerfile 更改

_贡献者：jirsat_

清理了一些未使用的依赖，并为 dockerfiles 添加了 ARM 支持。

## 修复

- 与楼层及较高楼层照明不更新相关的 bug
- 重新排列楼层在刷新前渲染错误
- Mac 上 Redo 无法使用
- 负值的计数器条显示为向左延伸
- 联合 DM 看不到私密先攻
- 移除最后一个楼层导致空白屏幕
- 移除活动楼层下方的楼层导致空白屏幕
- 可以将 unitSize 设置为 &lt; 1 的值

## 客户端重写详情

正如引言中所说，PA 现在使用 Vue 3，它引入了对 TypeScript 更友好的组合式 API（Composition API）。

所有 UI 代码都已完全重写以使用这个新 API。此外，所有 “store” 都已重写，改用自定义编写的非常简单的状态 API，更符合我自己的需求。这让我能够重构大量过去分散在纯 ts 文件和相关 store 中的代码。

Vue 3 的另一个优点是在响应式上下文中支持 Map 和 Set，这极大地改善了一些原本需要以不太理想的方式处理类 Map 数据的领域。
