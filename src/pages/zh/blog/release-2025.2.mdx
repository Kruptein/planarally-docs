新版本带来了一些好东西，不过它们主要面向 DM 和服务器所有者。

快速概览：

- 服务器配置格式已完全更改
- 服务器管理员现在可以配置邮件服务器，从而支持「忘记密码」流程
- isToken 属性已被移除，形状访问的工作方式也发生了变化
- 实验性的模组支持获得了一些改进
- 延续上一版本对游戏内素材管理器的重构
- 服务器新增匿名统计数据收集

<Warning title="服务器变更">
    如果你是服务器所有者，请注意：服务器配置发生了重大变更，需要手动干预，详情请见下文！

    服务器现在还使用 UV 进行依赖管理，这可能会影响你的升级方式。

</Warning>

## 邮件

这个功能早该有了：服务器所有者现在可以在（新的）配置中设置邮件服务器信息。配置完成后，PA 将能够使用它向玩家发送邮件。

目前它只有一个用途，但这是一个重要的用途：忘记密码流程。

_延伸阅读：[邮件配置部分](/zh/server/management/configuration/#mail)_

### 忘记密码

配置邮件后，登录界面会在密码标签下方显示一个「忘记密码？」操作，提供针对指定邮箱地址重置密码的流程。

请注意，只有用户配置了邮箱时此功能才有效（注意：注册时邮箱是可选项）。

一个附带的小体验改进是：当你在仪表板中修改邮箱地址时，现在会显示成功通知。此前，修改是否真的生效并不十分明确。

## 禁用视线渲染

作为 DM，你可能遇到过这样的情况：你正在制作一个新地点并配置了一大堆灯光，但因为启用了视线（LoS）而你的玩家还在另一个地点，你不确定这些灯光是否真的覆盖了你期望覆盖的范围。

围绕这个问题有一系列「土办法」：创建带有视野权限的临时形状、在地点设置中暂时禁用视线（LoS）等等……

它们都有效，但往往很麻烦，甚至容易出错（例如，当玩家准备前往该地点时，忘记重新开启视线设置）。

因此，工具栏下方现在为 DM 提供了一个新的快速开关，名为「LOS」。它只在地点启用视线（LoS）时可见，具有绿色（开启）和红色（关闭）两种模式，可用来仅在你的本地客户端覆盖视线设置。

这样你就可以快速开启/关闭该行为，而不会影响玩家，让关卡设计更轻松。

_延伸阅读：[快速开关](/zh/docs/tools/quick-toggles/)_

## 访问级别与 isToken

PA 中的每个形状都有访问级别，可以针对每位玩家进行微调，让一些玩家拥有对形状的完全编辑控制权，而其他玩家只有视野访问权限。

在此之前，这些访问级别（视野/移动/编辑）是叠加式的。每个访问级别也会授予与其下级访问级别相关的所有权限（例如，移动也包括视野权限）。在 PA 存在的大部分时间里，作为基准这运作良好，但最近我遇到了一些想要解决、却因这种叠加性质而无法实现的问题。

现在访问级别完全彼此独立。例如，现在可以拥有编辑访问权限而没有视野访问权限。如果玩家可以控制某个宠物的属性，却看不到宠物能看到的东西，这会很有用。

此外，每个形状还有一个特殊属性 `isToken`。当启用视线（LoS）时，它对视野计算至关重要，所有玩家形状都必须启用它。然而，这个属性对大多数新玩家来说并不直观，甚至一些老玩家也不完全确定它究竟有什么作用，只知道要启用它才能使用视线（LoS）。

这个属性很早就出于性能原因被引入，但经过一番思考，我发现如果修改访问级别的工作方式，它实际上并不需要。结果是 `isToken` 属性已被移除，不再需要手动为用户形状标记该属性。取而代之的是，只要你的用户对某个形状拥有视野访问权限，它就会像过去那样以 isToken 的形式渲染。

如果你想了解更多信息，我写过一篇[详细博客文章](https://www.planarally.io/blog/removing-is-token/)介绍这些变更的原因。

_延伸阅读：[形状访问](/zh/docs/game/shapes/#access)_

## 素材

仪表板中的素材管理器有专门的创建文件夹/上传文件/移除所选按钮，而游戏内版本没有。通过鼠标拖放和右键菜单仍然可以添加文件和移除所选，但创建文件夹就是不行。

现在游戏内的素材管理器也具备这些按钮。

此外，一些仍在使用旧版素材选择器界面的地方（例如战役标志设置器）都已更新为上一版本引入的新界面。

## 统计数据收集

我经常收到的一个问题是 PA 到底有多少用户，而我其实从来无法回答，甚至无法估算。

没有一个官方的 PA 服务器可以作为我估算的依据，我只有一些模糊的数字，比如 github 星标数或 discord 用户数，但这些并不能真正反映实际用户数量，而且如果它们能说明什么，那更可能代表的是服务器所有者而非玩家。

为了了解实际情况，我在服务器上引入了一个统计数据收集功能。在后续版本中，它还将与我计划对本地服务器管理所做的一些改动相结合，让这些统计在具备相应权限的情况下也能在仪表板中显示。

收集的统计数据非常简单，不包含任何个人信息。它们只是让我对实际活跃使用的用户/战役数量有一个大概了解。

有关具体统计哪些数据以及如何处理隐私的更多细节，请参见包含更多信息的 [github PR](https://github.com/Kruptein/PlanarAlly/pull/1608)。

对于服务器所有者，此功能可以使用新的配置格式进行配置。

## 模组更新

_请注意，模组支持仍处于非常实验性的阶段_

一年前添加了对模组的早期支持，当时还很粗糙，一个大问题是只有服务器所有者才能添加模组，即手动将它们放入特定文件夹。本次发布为每个战役添加了一个界面，允许 DM 上传该特定战役所使用的模组。

此外，模组 API 的许多内部实现都已更新，尤其是 DataBlock API 经历了一些大幅改动，使模组界面一侧变得更加紧凑。

planarally-mods 仓库中的所有示例模组也都已更新到新 API。

_延伸阅读：[模组 PR](https://github.com/Kruptein/PlanarAlly/pull/1583)_

## 服务器：配置变更

配置格式已完全更改，其在服务器文件夹中的存储位置也已更改。现在它采用基于 toml 的格式，并存储在数据文件夹中。这个变更背后的原因有很多，而且早就该做了。

**强烈**建议你阅读 [github PR](https://github.com/Kruptein/PlanarAlly/pull/1574) 中详细的原因和信息。

服务器文档已更新，展示了所有[配置选项](/zh/server/management/configuration/)。

如果你在升级现有配置文件时需要帮助，请随时联系 discord 服务器上的 #help 频道。

## 服务器：依赖管理变更

服务器现在也使用 [UV](https://docs.astral.sh/uv/) 进行依赖管理。

这意味着如果你使用 python/pip 手动管理服务器，也需要安装 uv 并采用新系统。这只会影响少数用户，因此影响应该不大。

更多信息请查看 [github PR](https://github.com/Kruptein/PlanarAlly/pull/1550) 和服务器 readme，其中已更新有关如何使用 uv 的信息。

## 错误修复

- 绘制工具的绘制多边形在形状完成前不会更新视野
- 减少移动玩家不拥有的棋子形状时的一些渲染开销
- 选择选项时形状右键菜单不关闭
- 切换模式时选择（Select）工具的 Build 界面不出现
- 房间和用户类别的 DataBlock 在服务器中存在阻止创建的问题
- 素材右键菜单移除功能不工作
- 游戏内素材右键菜单背景色有时不正确
- 仪表板素材管理器缺少素材上传栏
- 将拥有共享查看权限的素材拖到地图上不工作
