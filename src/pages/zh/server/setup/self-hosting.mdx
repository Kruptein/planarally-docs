# 自托管

## 常规信息

自行托管 PlanarAlly 需要比单纯使用现有服务更多的设置，但它能给你更多的控制权，并且你可以依赖它在离线状态下正常工作。

要自行托管 PlanarAlly，你有四种选择：

- 手动构建客户端并运行服务器
- 使用预构建的客户端运行服务器
- 使用 docker 容器
- 使用预编译的可执行文件

前两种方式需要你手动安装一些东西（例如 python、依赖项等）。\
Docker 可以让你省去大量手动工作，但需要理解容器和卷的概念。

最后，.exe 适用于不太熟悉技术的人。它应该能满足需求，但测试较少。

### 版本

根据你选择的方式，你可以决定使用哪个 PA 版本。

正式版本可在[这里](https://github.com/Kruptein/PlanarAlly/releases)找到官方发布。\
开发版本可以检出任意 git 提交/分支并手动构建。\
所有正式版本以及开发分支的 docker 镜像都会自动发布到 [dockerhub](https://hub.docker.com/r/kruptein/planarally/tags) 上。

### 备份与升级

备份数据时，有三个文件夹很重要（相对于服务器文件夹）：

- data
- static/assets
- static/mods

如果你修改过配置（`data/config.toml`），可能还需要备份其他一些文件夹/文件。

升级 PA 时，可能需要对存档文件（默认位置为 `data/planar.sqlite`）进行迁移。当前存档文件的备份会保存到 `save_backups` 文件夹中。

<Info>
如果你使用官方发布的 zip/tarball 安装 PA（例如将文件夹解压到某个位置），通常建议将这些文件解压到一个新位置，然后移动/复制上述 3 个数据文件夹。
<br />
在现有安装之上解压通常可以工作，但有时会导致一些隐蔽的问题，例如某个文件已从代码库中移除，但通过覆盖操作并不会被删除。
<br />
使用 git/docker 时则不适用此情况。

</Info>

### 配置

找不到配置文件是正常的。PA 使用内部存储的默认值。
要覆盖其中一些选项，你可以在服务器的 `data` 文件夹中创建一个 `config.toml` 文件来更改配置。

详细内容请参阅[配置文档](/zh/server/management/configuration/)。

默认情况下，PA 会在 8000 端口上运行，所以无论选择哪种托管方式，只要一切顺利，你都应该能在 http://localhost:8000 看到 PA。

<Info>
    没有预配置的管理员用户，所以当你看到登录页面时，你需要像其他用户一样走注册流程！

    <br/>

    如果你愿意，可以通过创建/修改服务器配置，将你创建的用户设置为管理员，以看到一些额外的界面。

</Info>

## 完全手动安装

PA 由两部分组成：

- 用 python 编写的服务器
- 用 typescript 编写的前端

虽然使用 PA 总是需要运行服务器，但你只需要在下载/更换 PA 版本时重新构建客户端。

### 前端

要构建前端，你需要安装 `node` 和 `npm`。在撰写本文时，至少需要 node 22 版本。（不过，如果你还没有安装 node，我建议使用 24 版本）

```bash
# You need to be in the client folder to get the client working!
cd client
# Update dependencies, a new version usually comes with new dependencies
npm i
# Build the server
npm run build
```

这将把 typescript 文件转换成几个压缩后的 javascript 文件，并将它们放在服务器的 static 文件夹中，以便服务器可以运行。

就这么简单！

### 后端

运行 PA 需要安装较新版本的 python。我认为 3.11 是最低版本，但官方测试使用的是 3.13。

你可以使用任何方式安装 python，但推荐使用 [uv](https://docs.astral.sh/uv/getting-started/installation/)。
它可以将不同的 python 安装干净地分隔开，而且速度极快。此外，PA 本身也使用它进行依赖管理。

<Info title="不使用 uv 的依赖">
如果你不想或无法使用 uv，请注意仓库中没有 `requirements.txt` 文件。
PA 使用现代的 `pyproject.toml` 文件，uv（以及其他工具）都能理解它。

但这意味着你不能使用传统的 `pip install -r requirements.txt`。你可以在上面提到的 `pyproject.toml` 文件中找到需要安装的依赖列表。

</Info>

以下说明假定你使用 uv，如果使用其他方式，请根据需要调整命令。

```bash
# 1. Install python (can be skipped if you already have this)
uv python install 3.13
# 2. Move to the server folder!
# (if you're still in the client folder you need to use `cd ../server`!)
cd server
# 3. Create a virtual environment for your python install
uv venv
# 4. Install the dependencies
uv sync
# 5. Run PA
uv run planarally.py
```

将来想要（重新）启动服务器时，你只需运行第 5 步（在服务器文件夹中）。

## 预构建客户端

如果你想管理服务器安装，但不想费心构建客户端，可以使用预构建的客户端文件。
它们以发布版中的 `Planarally-bin` 文件形式出现。

这些只包含一个 server 文件夹，你可以按照上面的完全手动安装步骤操作，但跳过所有与前端/客户端相关的步骤。

## Docker 容器

### 原版

你可以通过以下命令获取[官方容器](https://hub.docker.com/r/kruptein/planarally)。
`docker pull kruptein/planarally`

要实现数据持久化，需要挂载 3 个卷：

- data：这里通常存放配置和存档文件
- assets：这里存放用户上传的素材
- mods：这是一个可选卷，仅当你允许/在服务器上使用 mods 时才需要。

建议使用 `docker volume create` 为这些卷创建显式的卷（参见 https://docs.docker.com/storage/volumes/）

PA 在 docker 容器中以受限用户身份运行，你需要更改已创建卷的所有权以匹配该用户：

```
cd /var/lib/docker/volumes
sudo chown -R 9000:9000 data/
# repeat for other volumes
```

设置好卷之后，你就可以真正运行容器了。

```
# PA runs on port 8000, You can drop the mods volume if you don't intend to use it or allow it
# It's generally recommended to specify a particular tag of the docker image (e.g. v2025.2.2) instead of using the latest
# New versions can come with database migrations and might require some manual intervention that you want to do when you have some time
docker run -d -t -p 8000:8000 -v data:/planarally/data/ -v assets:/planarally/static/assets/ -v mods:/planarally/static/mods --name planarally kruptein/planarally
```

### compose

目前没有官方的 docker-compose 文件，但一位社区成员曾写过[这份指南](https://github.com/edmael/selfhosted-planarally)，介绍如何使用 docker-compose、ssl 和 nginx。

此外，为 Traefik 反向代理制作的示例配置中也包含一个 compose 文件，可以在[这里](/zh/server/advanced/proxy/#traefik)找到。

## 预编译可执行文件

_请注意，本教程省略了发布文件名称中的版本号。_

要在 Windows 上运行 PlanarAlly，请从发布页面下载 `planarally-windows.zip`，并将其解压到一个新文件夹中。

这个文件夹包含许多不同的文件，但你现在需要关注的是名为 `planarally.exe` 的文件。
执行该文件时，会出现一个命令提示符窗口（黑屏并显示一些文字）。

<Warning>
    对互联网上的随机可执行文件保持警惕是明智的。这些 `.exe` 文件是在隔离的 CI 环境中使用 Nuitka 从
    python 源代码生成的。

    尽管如此，某些杀毒软件厂商仍有可能出于各种原因触发误报。

</Warning>

## 开发

你可以配置客户端和服务器以特殊的开发模式运行。这样前端就会热重载（即所做的更改会立即生效，无需重新构建）。

这要求服务器使用额外的 'dev' 参数运行：

```bash
uv run planarally.py dev
```

此外，这还需要一个单独进程来处理客户端的热重载：

```bash
# in the client folder
npm run dev
```

<Warning>
    客户端输出会提到一个特定的端口，你应该完全忽略它，因为 PA 开发服务器以一种特殊的方式连接，
    使其与常规设置尽可能相似。
    <br />
    因此，你仍然可以使用与之前相同的（服务器）端口访问 PA。
</Warning>

<Warning>
    如果这是仓库的全新版本，那么在使用开发服务器之前，客户端必须先正常构建一次。 否则，服务器上会缺少一些生成的文件。
</Warning>
