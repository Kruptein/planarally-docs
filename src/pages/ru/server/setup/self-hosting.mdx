# Свой сервер

## Общая информация

Собственное размещение PlanarAlly требует чуть больше настройки, чем просто использование готового сервиса, но при этом даёт вам больше контроля и позволяет рассчитывать на работу в автономном режиме.

Чтобы разместить PlanarAlly самостоятельно, у вас есть четыре варианта:

- собрать клиент вручную и запустить сервер;
- запустить сервер с предварительно собранным клиентом;
- использовать docker-контейнер;
- использовать предкомпилированный исполняемый файл.

Первые два варианта требуют ручной установки некоторых компонентов (например, python, зависимостей, ...).\
Docker позволяет пропустить большую часть ручной работы, но требует понимания контейнеров и томов.

Наконец, для тех, кто не особо разбирается в технических деталях, доступен файл `.exe`. Он должен справиться со своей задачей, но протестирован хуже.

### Версии

В зависимости от выбранного варианта вы можете решить, какую версию PA использовать.

Для production-версий официальные релизы можно найти [здесь](https://github.com/Kruptein/PlanarAlly/releases).\
Для версии для разработки достаточно просто переключиться на любой коммит/ветку git и собрать её вручную.\
Для всех релизов, а также для ветки разработки docker-образы публикуются автоматически на [dockerhub](https://hub.docker.com/r/kruptein/planarally/tags).

### Резервные копии и обновления

При создании резервных копий данных важны три папки (относительно папки сервера):

- data
- static/assets
- static/mods

Если вы вносили изменения в конфигурацию (`data/config.toml`), возможно, потребуется также скопировать и некоторые другие папки/файлы.

При обновлении PA может произойти миграция файла сохранения (по умолчанию он находится в `data/planar.sqlite`). Резервная копия текущего файла сохранения будет помещена в папку `save_backups`.

<Info>
Если вы устанавливаете PA из одного из релизных zip/tar-архивов (например, распаковываете папку куда-нибудь), как правило, рекомендуется распаковывать их в новое место и переносить/копировать указанные выше 3 папки с данными.
<br />
Распаковка поверх существующей установки обычно работает, но иногда может привести к скрытым багам, когда файл был удалён в кодовой базе, но не будет удалён при перезаписи.
<br />
При использовании git/docker это не актуально.

</Info>

### Конфигурация

Это нормально, что вы не находите файл конфигурации. PA использует значения по умолчанию, которые хранятся внутри.
Чтобы переопределить часть этих настроек, вы можете создать файл `config.toml` в папке `data` сервера и изменить конфигурацию.

Подробности см. в [документации по конфигурации](/ru/server/management/configuration/).

По умолчанию PA запускается на порту 8000, поэтому если всё прошло успешно — независимо от выбранного варианта размещения — вы должны увидеть PA по адресу http://localhost:8000

<Info>
    Заранее настроенного пользователя-администратора нет, поэтому, когда вы увидите страницу входа, вам придётся пройти процесс регистрации
    как и любому другому пользователю!

    <br/>

    При желании вы можете настроить созданного пользователя как администратора, чтобы увидеть часть дополнительного интерфейса, создав/изменив конфигурацию сервера.

</Info>

## Полностью ручная установка

PA состоит из двух частей:

- сервер, написанный на python;
- фронтенд, написанный на typescript.

Хотя для работы PA вам всегда нужно запускать сервер, пересобирать клиент нужно только при загрузке/смене версии PA.

### Фронтенд

Для сборки фронтенда вам понадобятся установленные `node` и `npm`. На момент написания статьи требуется как минимум версия 22 node. (Хотя я бы порекомендовал версию 24, если у вас ещё не установлен node)

```bash
# You need to be in the client folder to get the client working!
cd client
# Update dependencies, a new version usually comes with new dependencies
npm i
# Build the server
npm run build
```

Это преобразует typescript-файлы в несколько минифицированных javascript-файлов и поместит их в папку static сервера, чтобы сервер можно было запустить.

Вот и всё!

### Бэкенд

Для запуска PA вам понадобится установленный python свежей версии. Полагаю, минимальная версия — 3.11, но официально протестирована версия 3.13.

Вы можете использовать любой способ установки python, но рекомендуемый путь — через [uv](https://docs.astral.sh/uv/getting-started/installation/).
Это аккуратно разделяет установки python и работает невероятно быстро. Кроме того, сам PA использует его для управления зависимостями.

<Info title="Зависимости без uv">
Если вы не хотите или не можете использовать uv, стоит отметить, что в репозитории нет файла `requirements.txt`.
PA использует современный файл `pyproject.toml`, который понимает uv (а также другие инструменты).

Это, однако, означает, что вы не можете выполнить традиционную команду `pip install -r requirements.txt`. Список зависимостей, которые вам нужно установить, можно найти в упомянутом файле `pyproject.toml`

</Info>

Следующие инструкции предполагают использование uv; если вы используете другой подход, адаптируйте команды под свои нужды.

```bash
# 1. Install python (can be skipped if you already have this)
uv python install 3.13
# 2. Move to the server folder!
# (if you're still in the client folder you need to use `cd ../server`!)
cd server
# 3. Create a virtual environment for your python install
uv venv
# 4. Install the dependencies
uv sync
# 5. Run PA
uv run planarally.py
```

Когда вы захотите (пере)запустить сервер в будущем, достаточно будет выполнить только шаг 5 (в папке сервера).

## Предварительно собранный клиент

Если вы хотите управлять установкой сервера, но не хотите возиться со сборкой клиента, вы можете использовать файлы предварительно собранного клиента.
Они появляются в релизах как файлы `Planarally-bin`.

В них есть только папка сервера; вы можете следовать тем же шагам, что и при полностью ручной установке выше, но пропустить все шаги, связанные с фронтендом/клиентом.

## Docker-контейнер

### Vanilla

Вы можете получить [официальный контейнер](https://hub.docker.com/r/kruptein/planarally) с помощью этой команды.  
`docker pull kruptein/planarally`

Существует 3 тома, которые следует смонтировать для сохранения данных:

- data: здесь обычно хранится конфигурация, а также файл сохранения;
- assets: здесь хранятся загруженные пользователями активы;
- mods: необязательный том, требуется только если вы разрешаете/используете моды на сервере.

Рекомендуется создавать для них явные тома с помощью `docker volume create` (см. https://docs.docker.com/storage/volumes/)

PA запускается в docker-контейнере от ограниченного пользователя; вам нужно изменить владельца созданных томов, чтобы они соответствовали этому:

```
cd /var/lib/docker/volumes
sudo chown -R 9000:9000 data/
# repeat for other volumes
```

Когда тома настроены, можно запускать контейнер.

```
# PA runs on port 8000, You can drop the mods volume if you don't intend to use it or allow it
# It's generally recommended to specify a particular tag of the docker image (e.g. v2025.2.2) instead of using the latest
# New versions can come with database migrations and might require some manual intervention that you want to do when you have some time
docker run -d -t -p 8000:8000 -v data:/planarally/data/ -v assets:/planarally/static/assets/ -v mods:/planarally/static/mods --name planarally kruptein/planarally
```

### compose

Официального docker-compose-файла пока нет, но один из участников сообщества однажды написал [это руководство](https://github.com/edmael/selfhosted-planarally) по использованию docker-compose, ssl и nginx.

Также в пример настройки для обратного прокси Traefik включён compose-файл, который можно найти [здесь](/ru/server/advanced/proxy/#traefik).

## Предкомпилированный исполняемый файл

_Обратите внимание, что номера версий, входящие в названия файлов релизов, в этом руководстве опущены._

Чтобы запустить PlanarAlly на Windows, скачайте `planarally-windows.zip` со страницы релизов и распакуйте его в новую папку.

В этой папке много разных файлов, но самый важный для вас сейчас — тот, который называется `planarally.exe`.
При его запуске появится командная строка (чёрное окно с каким-то текстом).

<Warning>
    Здорово относиться с подозрением к случайным исполняемым файлам из интернета. Эти файлы `.exe` генерируются с помощью Nuitka из
    исходного кода на python в изолированном CI-окружении.

    Тем не менее может случиться так, что какой-нибудь антивирусный вендор по различным причинам выдаст ложное срабатывание.

</Warning>

## Разработка

Вы можете настроить клиент и сервер для работы в специальном режиме разработки. Так фронтенд будет перезагружаться на лету (т.е. изменения применяются сразу, без пересборки).

Для этого сервер нужно запускать с дополнительным аргументом 'dev':

```bash
uv run planarally.py dev
```

Кроме того, требуется отдельный процесс, отвечающий за hot-reload клиента

```bash
# in the client folder
npm run dev
```

<Warning>
    Вывод клиента будет упоминать какой-то конкретный порт — полностью проигнорируйте его, поскольку dev-сервер PA
    подключён особым образом, чтобы быть максимально похожим на обычную настройку.
    <br />
    Поэтому вы по-прежнему обращаетесь к PA через тот же (серверный) порт, что и раньше.
</Warning>

<Warning>
    Если это чистая версия репозитория, перед использованием dev-сервера клиент должен быть один раз собран обычным
    образом. В противном случае будет не хватать некоторых файлов, которые генерируются на сервере.
</Warning>
