# Конфигурация

<Warning title="Последние изменения">
    Конфигурация сервера была полностью изменена в выпуске 2025.2. Конфиг, описанный в этом документе, относится к
    новому формату.
</Warning>

По умолчанию конфигурационный файл **отсутствует**. Вместо этого PA использует значения по умолчанию для всех настроек. Значения конфига по умолчанию можно посмотреть [здесь](#default-config)

Чтобы изменить поведение, создайте файл `config.toml` в папке `data` сервера.

Если указан частичный конфиг, недостающие поля/разделы будут заменены значениями по умолчанию, где это применимо.

# Формат

Как следует из расширения конфига, конфиг оформляется в формате [TOML](https://toml.io/en/).

Конфиг разбит на небольшие разделы, у каждого из которых есть заголовок `[раздел]`, а подразделы обозначаются как `[раздел.какой.то.подраздел]`.
После каждого (под)раздела следуют отдельные строки для настройки конкретных значений.

Подробная информация о том, как работает формат TOML, выходит за рамки этого документа, но после просмотра конфига по умолчанию у вас должно сложиться хорошее представление о том, как он работает.

# Конфиг по умолчанию

```toml
[general]
save_file = "data/planar.sqlite"
allow_signups = true
enable_export = true

[assets]
max_single_asset_size_in_bytes = 0
max_total_asset_size_in_bytes = 0

[webserver]
max_upload_size_in_bytes = 10485760

[webserver.connection]
type = "hostport"
host = "0.0.0.0"
port = 8000

[[logging]]
mode = "stdout"
level = "INFO"
```

<Info title="Пути к файлам">
    При указании путей к файлам или папкам вы можете использовать абсолютные пути (например, `/home/user/example.txt`)
    или относительные пути (например, `data/planar.sqlite`). При использовании относительного пути он будет вычисляться
    относительно основной папки сервера, а НЕ той папки, где находится конфиг.
</Info>

# Разделы

Здесь будут перечислены все возможные варианты вместе с их значениями по умолчанию.

## Общие

Название раздела: `general`

### Поле: `save_file`

По умолчанию: `"data/planar.sqlite"`\
Тип: `string`

Путь к файлу сохранения. Это критически важная настройка, изменение которой окажет большое влияние. Файл сохранения следует надлежащим образом резервировать[^1].

Если сервер запускается и выбранный путь не существует, сервер создаст новый файл сохранения.

<Info title="Формат файла сохранения">
    Обратите внимание, что на данный момент PlanarAlly поддерживает хранение сохранений только в формате sqlite.
</Info>

<Warning>
    Пока сервер работает, могут создаваться дополнительные файлы базы данных (например, `planar.sqlite-shm` и `planar.sqlite-wal`).
    Файл `planar.sqlite-wal` (журнал упреждающей записи) необходим для базы данных сохранения, и данные будут потеряны, если его не сохранить.
    Файл `planar.sqlite-shm` (разделяемая память) не является критичным, и его резервировать не нужно.

    При корректном завершении работы сервера эти файлы будут удалены. Однако они могут остаться, если серверу не удалось остановиться аккуратно.
    При копировании файла сохранения обязательно скопируйте и эти файлы, если они существуют, иначе ваше сохранение может оказаться повреждённым или устаревшим.

</Warning>

### Поле: `admin_user`

По умолчанию: нет — необязательное поле\
Тип: `string`

Если здесь указано имя пользователя, этот пользователь будет считаться основным администратором.
Ему будут доступны дополнительные функции в дашборде для управления такими вещами, как пользователи и кампании на сервере.

### Поле: `client_url`

По умолчанию: нет — необязательное поле\
Тип: `string`\
_Обычно рекомендуется настроить это поле, но для минимальной установки оно не требуется._

При задании это должен быть полный базовый URL фронтенд-приложения. (например, "https://app.planarally.io").

Оно используется в URL приглашения и в письмах восстановления пароля. Если значение отсутствует, URL приглашения при генерации будет определяться по текущему URL в браузере. URL в письмах, однако, **не** будут содержать информацию о корневом URL, поскольку сервер не может его предугадать.

### Поле: `allow_signups`

По умолчанию: `true`\
Тип: `boolean`

Эта настройка определяет, могут ли пользователи регистрировать новую учётную запись через фронтенд. Если она отключена, создание учётных записей доступно только путём манипуляций с базой данных.

### Поле: `enable_export`

По умолчанию: `true`\
Тип: `boolean`

Если эта настройка включена, пользователям доступен экспорт **и** импорт учётной записи.

Обычно это рекомендуется, поскольку позволяет пользователям переносить свои данные на другой сервер или с него, а также предоставлять мне данные для отладки.

## Веб-сервер

Название раздела: `webserver`

Один из самых важных разделов для настройки — веб-сервер.
Он включает важный подраздел `connection`, который нужно настроить, чтобы решить, как сервер PA будет связан с внешним миром.

<div id="subsection">

### Подраздел: `connection`

_Это подраздел (см. [Конфиг по умолчанию](#default-config) для примера того, как его настроить)._

Здесь настраивается, как сервер подключён к сетевому стеку. Это должна быть либо конфигурация HostPort, либо конфигурация сокета.
По умолчанию используется комбинация HostPort.

#### поле: `type`

По умолчанию: `"hostport"`\
Тип: `"hostport" или "socket"`

Поле type в конечном счёте определяет, какой тип подключения используется.

```toml
# Настроено либо подключение hostport
[webserver.connection]
type = "hostport"
...

# Либо подключение socket
[webserver.connection]
type = "socket"
...
```

#### Поля HostPort

#### поле: `host`

По умолчанию: `"0.0.0.0"`\
Тип: `string`

IP-адрес, к которому сервер попытается привязаться.

#### поле: `port`

По умолчанию: `8000`\
Тип: `integer`

Порт, к которому сервер попытается привязаться.

Убедитесь, что используемый вами порт не занят другим приложением.
Также убедитесь, что используемый порт доступен снаружи машины.
Особенно при запуске в частной сети (например, дома) вам, возможно, потребуется включить _проброс портов_ в конфигурации вашего роутера.

#### Пример конфига HostPort

```toml
[webserver.connection]
type = "hostport"
host = "192.168.0.1"
port = "80"
```

#### Поля Socket

#### поле: `socket`

По умолчанию: нет\
Тип: `string`

Путь к сокету, который будет использоваться для привязки.

#### Пример конфига Socket

```toml
[webserver.connection]
type = "socket"
socket = "/var/run/pa.sock"
```

</div>

<div id="subsection">

### Подраздел: ssl

Это необязательный подраздел; если его опустить, к самому серверу PA никакая конфигурация SSL не применяется.
Это не мешает вам настроить SSL выше по цепочке (например, в вашем обратном прокси).

Настоятельно рекомендуется убедиться, что SSL настроен где-то в цепочке!

#### Поле: `enabled`

По умолчанию: `false`\
Тип: `boolean`

Позволяет включать/отключать конфигурацию SSL, не удаляя полностью раздел SSL и не комментируя его.
Только когда этому значению присвоено `true`, конфигурация SSL будет фактически применена.

#### Поле: `fullchain`

По умолчанию: нет\
Тип: `string`

Путь к полному цепочному сертификату.

#### Поле: `privkey`

По умолчанию: нет\
Тип: `string`

Путь к сертификату закрытого ключа.

#### Пример конфига SSL

```toml
[webserver.ssl]
enabled = true
fullchain = "/etc/letsencrypt/live/planarally/fullchain.pem"
privkey = "/etc/letsencrypt/live/planarally/privkey.pem"
```

</div>

### Поле: `cors_allowed_origins`

По умолчанию: нет (необязательное поле)\
Тип: `string / список строк`

Конфигурация CORS для вебсокет-сервера.

Это значение передаётся серверу socketio, больше информации можно найти в документации [socketio](https://python-socketio.readthedocs.io/en/latest/api.html#asyncserver-class).
Значение `'*'` можно задать, чтобы разрешить все источники; это полезно для целей тестирования, но небезопасно.

Эту настройку часто приходится задавать либо как подстановочное значение (\*), либо как корректный конкретный домен, чтобы всё заработало!
Консоль сервера должна регистрировать, когда подключение было отклонено из-за cors.

### Поле: `max_upload_size_in_bytes`

По умолчанию: `10_586_760` (10 \* 1024 \*\* 2 == 10 MB)\
Тип: `integer`

Максимальный размер одной загрузки данных от клиента.

Следует отметить, что это в основном работает как стратегия разбиения на части.
Загрузка активов и передача кампаний будут разбиваться на части согласно этому максимуму, но общий размер этих данных, таким образом, может превысить лимит!
Информацию о том, как ограничить размер активов пользователей, см. в разделе assets конфига.

## Почта

Название раздела: `mail`

Это необязательный раздел, по умолчанию он не включён.

В настоящее время он используется только для отправки писем в рамках процедуры восстановления пароля.

### Поле: `enabled`

По умолчанию: `false`\
Тип: `boolean`

Позволяет включать/отключать конфигурацию почты, не удаляя полностью раздел и не комментируя его.
Только когда этому значению присвоено `true`, конфигурация почты будет фактически применена.

### Поле: `host`

По умолчанию: нет\
Тип: `string`

Хост SMTP-почтового сервера, это поле обязательно к заполнению.

### Поле: `port`

По умолчанию: нет\
Тип: `integer`

Порт SMTP-почтового сервера, это поле обязательно к заполнению.

### Поле: `username`

По умолчанию: нет (необязательное)\
Тип: `string`

При необходимости можно указать имя пользователя для аутентификации.

### Поле: `password`

По умолчанию: нет (необязательное)\
Тип: `string`

При необходимости можно указать пароль для аутентификации.

### Поле: `default_from_address`

По умолчанию: нет\
Тип: `email-string`

Адрес электронной почты по умолчанию, используемый при отправке писем.

### Поле: `ssl_mode`

По умолчанию: `"starttls"`\
Тип: `Literal["ssl", "tls", "starttls", "lmtp"]`\
Добавлено: v2025.2.1

Здесь настраивается используемый режим подключения клиента.
По умолчанию используется метод starttls, который должен покрывать широкий спектр случаев.

Иногда он может работать некорректно; в этом случае вместо него можно попробовать режим `"ssl"` или любой другой режим.

## Статистика

Название раздела: `stats`

Это необязательный раздел; если он не указан, используется набор значений по умолчанию.
Он управляет сбором и передачей анонимной статистики использования.

См. [этот github PR](https://github.com/Kruptein/PlanarAlly/pull/1608) для получения информации о том, что собирается и зачем.

### Поле: `enabled`

По умолчанию: `true`\
Тип: `boolean`

Позволяет включать/отключать конфигурацию почты, не удаляя полностью раздел и не комментируя его.
Если задано значение `false`, сбор статистики не будет производиться вообще.

### Поле: `enable_export`

По умолчанию: `true`\
Тип: `boolean`

Позволяет отключить экспорт статистики на сервер статистики PA.
Локальный сбор при этом будет продолжаться.

### Поле: `export_frequency_in_seconds`

По умолчанию: `24 * 60 * 60` (1 день)\
Тип: `int`

Определяет, как часто статистика отправляется на сервер статистики PA.

Не рекомендуется ставить это значение ниже 1 дня.
Рекомендуемые интервалы: 1 день, 1 неделя или 1 месяц.

### Поле: `stats_url`

По умолчанию: `https://stats.planarally.io`
Тип: `string`

URL приёма данных статистики.

## Журналирование

Название раздела `logging`

Это необязательный раздел, и его конфигурация по умолчанию — ведение журнала в стандартный вывод на уровне "INFO".

<Info title="Несколько записей">
    Раздел журналирования можно указывать несколько раз, чтобы настроить несколько файлов вывода. Поэтому заголовок
    раздела должен быть записан как `[[logging]]`
</Info>

### Поле `level`

По умолчанию: `INFO`\
Тип: `Literal["DEBUG", "INFO", "WARNING", "ERROR", "CRITICAL"]`

Уровень, на котором будет выводить этот регистратор. Уровни выше также регистрируются на этом уровне. Например, если установить ERROR, в этот вывод будут записываться и ERROR, и CRITICAL

### Поле `mode`

Тип: `Literal["stdout", "file"]`

Если указать stdout, единственное доступное другое поле — level.

Вот пример журналирования, который устанавливает стандартный вывод на critical

```toml
...
[[logging]]
mode = "stdout"
level = "CRITICAL"
...
```

### Поле `file_path`

По умолчанию: `data/planarally.log`\
Тип: `string`

Задаёт путь вывода для журнала на основе файла. При использовании docker рекомендуется использовать папку data, чтобы она была доступна за пределами контейнера.

### Поле `max_log_size_in_bytes`

По умолчанию: `200_000`\
Тип: `int`

Максимальный размер файла журнала, после которого он будет ротирован в следующий файл.

### Поле `max_log_backups`

По умолчанию: `5`\
Тип: `int`

Количество резервных файлов, которые нужно хранить; более старые файлы будут автоматически удалены.

Вот пример настройки файлового регистратора, у которого только 2 резервных файла. Его можно комбинировать с примером стандартного вывода, чтобы выводить и в стандартный вывод, и в файл.

```toml
...
[[logging]]
mode = "file"
level = "INFO"
max_log_backups = 2
...
```

## Активы

Название раздела `assets`

Это необязательный раздел.

### Поле `max_single_asset_size_in_bytes`

По умолчанию: `0`\
Тип: `int`

Максимальный размер в байтах, который может иметь недавно загруженный актив.
Если это поле `<= 0`, оно рассматривается как «без ограничений».

Следует отметить, что это влияет только на новые загрузки активов. Изменение значения не повлияет на уже существующие активы.

### Поле `max_total_asset_size_in_bytes`

По умолчанию: `0`\
Тип: `int`

Максимальный размер в байтах, который пользователю разрешено загрузить суммарно.
Если это поле `<= 0`, оно рассматривается как «без ограничений».

Актив будет отклонён, если его размер приведёт к превышению общего разрешённого для пользователя значения.
Следует отметить, что это влияет только на новые загрузки активов. Изменение значения не повлияет на уже существующие активы.

[^1]: В документации SQLite описывается важность файлов [-wal](https://www.sqlite.org/tempfiles.html#write_ahead_log_wal_files) и [-shm](https://www.sqlite.org/tempfiles.html#shared_memory_files).
